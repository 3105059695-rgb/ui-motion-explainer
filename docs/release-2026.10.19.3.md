# 2026.10.19.3：把口播选用接到真实工程

本版处理“资源在 Skill 里，新对话却没有真正调用”的问题。保留四层和唯一入口，不再增加一个需要用户另行触发的剪辑 Skill。

## 实际改动

- `direct prepare` 按本期口播及上下文检索来源方法、语义配方和实现候选，附原句、时间段、逐句行号、适用与避用条件、文件可用状态。候选由 Agent 阅读和取舍，不能当作自动完成的分镜。
- 当前导演计划记录每段采用参考、原创或保留人物的理由，以及 AIGC 用不用及原因。正式导出绑定原稿覆盖、实际素材、当前画风、输出时间、实现文件和入口真正引用的时间线；旁边放一份无关 JSON 或只写文档不能通过这层检查。
- 统一入口在完整渲染后检查实际媒体的哈希、视频/音频流和时长，并复查原稿、计划、实现的绑定。区间预览或静帧明确标为预览，不能冒充整片交付。
- 修复主流程中的旧目录断链，恢复 230 条参考目录的来源 URL。两套随包起点、226 条可接续的历史源码记录、两条纯目录记录分开表示，旧的运行声明留在历史字段，不能冒充本次运行结果。
- 可选本机映射接回保留的研究原片与参考源码，统一入口自动读取；包内渲染器仍优先，只有明确配置的 reference 库使用本机补充。安装更新保留映射，公开包排除这些私人路径。
- 保留 Fred 黑紫正文方向、三张校准图、AIGC 手绘画风参考与既有源码。例图不固定成本期女孩、首帧或场景菜单；新稿按意思设计，当前项目明确固定 IP 时才保持其身份。
- 实跑发现普通 HTTP 视频寻帧会退回首帧，已为两个渲染器和本地预览接入共享 Range 服务。支持精确单区间读取，不需把整条大视频加载进内存；Chromium 非零时间定位与实际像素变化已验证。
- 安装冲突检查发现方木档案另有最新用户纠正，已合并其黑紫 UI 选择并接到当前合同。账号人物、声音、开头和明确选用的白板模式保留；私有工程链接在公开档案中明确标为未随包。

## 验证

本机脚本测试 203 项：188 通过、15 项因需显式本机条件跳过。安装/更新测试 16 项：15 通过、1 项因本机符号链接权限跳过。合计 219 项，203 通过、16 跳过，无失败。发布工作流在 Linux 和 Windows 再执行清单、脚本及安装检查；状态以本版本对应 Actions 为准。

主流程 16 份文档共 267 条本地链接通过检查；11 个必需模块、3 张 Fred 校准图和 10 张 AIGC 画风/场景参考图存在。私人资源核对得到 6 条研究原片哈希匹配、17 份研究文件和 228 个历史源码目录/入口存在；这些历史工程本次没有逐项渲染，未放入公开包的原视频和旧预览没有被伪造为可用。

独立上下文制作测试只提供 Skill 入口、完整原稿/原声和三段已有动作素材，没有追加风格说明，也未读取历史完整成片或旧工程实现。实际产出 11.30 秒、1920×1080、30 fps、339 帧样片，包含三段动作、遮挡衔接和收拢后的黑紫结果 UI。它复用现有 AIGC 片段，不是本次重新调用生成模型。

统一生产检查、完整解码、浏览器实际时间线/媒体请求和原声音轨核对通过；7 个编码画面对照点与源时间匹配，13 个最终抽帧已查看。已修复首帧冻结、转场标题压图及预览尾帧问题。原 WAV 字节未改，编码音轨相关性 0.99999383；这不是主观听审。样片使用完整素材 Blob 解决当时的服务取帧问题；新增共享 Range 服务另外通过 19 项实际 HTTP 测试和 Chromium 无 Blob 红/蓝画面跨时间定位测试。

## 检查边界

- 自动候选是离线检索辅助，不能代替对句意、上下文和画面的判断。
- 实现绑定是静态依赖、文件哈希及映射检查，不能证明 JavaScript 每条分支实际执行，也不能对画面做审美判定。实际运行、导出画面、正常速度视听和用户认可分开记录。
- 当前成片绑定与 `verify-output` 适配 base/fusion/director 的 `index.html` 入口；自定义 Editorial/Remotion 工程还不能宣称通过同一输出合同。
- 本机已保留源码不等于公开安装也拥有。来源 URL 未在本次联网逐一验证；230 条目录不等于 230 个本版验证完的效果。
- 旧稿件和计划保留可读；缺当前选用与实现证据时不能冒充生产就绪。已确认风格不因换稿撤销，新样片也不自动继承用户认可。
