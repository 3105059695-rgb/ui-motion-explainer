# 视觉与节奏

## 风格定位

这是一种以界面为素材的科技知识讲解：黑白与淡紫构成统一画面，抽象概念变成文档、窗口、状态标签、卡片和关系图；真实产品操作穿插其中。用户认可的是这种连续变化、干净排版和信息节奏，并非只认可某个卡片模板。

下列值是重建时可用的起点，不是对原工程的参数测量。三条原片均为 1920×1080 / 30fps；用户要求其他画幅时重新排版，而非中心裁切。

## 设计变量

| 项目 | 建议起点 | 使用方式 |
|---|---|---|
| 主画布 | `#FFFFFF` | 大面积留白 |
| 字与深色窗口 | `#101112` | 主文案、深底卡片 |
| 次级底色 | `#F3F4F5` | 次级控件、浅色卡片 |
| 淡紫 | `#CDB7F5` | 深底重点字、选区、状态高亮 |
| 白底紫色字 | `#7451B8` | 防止浅紫在白底过淡 |
| 中文字体 | 本地可用的粗无衬线，400 / 700 | 成片打包实际使用字形，不能仅依赖系统安装 |
| 大标题 | 70–90 px | 通常一到两行，按长度调节 |
| 主对象标题 | 34–54 px | 卡片、窗口、结果短句 |
| 图解正文 | 25–34 px | 简化表格与说明；非关键元信息可略小 |
| 字幕 | 40–46 px | 底部居中，优先一行，长句按语义分段 |
| 大数字 | 110–200 px | 只用于真正需要对比的量级 |
| 圆角 | 18–30 px | 卡片与窗口；内控件用较小圆角 |
| 阴影 | `0 24px 40px -26px #10111244` | 轻微层次，不做厚重发光 |
| 内容安全区 | 左右约 100–140 px，顶部约 90–130 px | 正文避让字幕，下部预留约 145–175 px |

缩小到最终观看尺寸检查。不能为了保住表格的所有列而把主要内容变成蚂蚁字。演示图解可删去无关列；真实录屏用局部聚焦，保留必要的操作上下文。

## 组件习惯

- **窗口**：深色顶栏、浅/深正文、适量系统圆点；顶栏不是装饰主角。产品专属元素按真实来源处理。
- **文档**：标题 + 少量可读字段 + 次要灰线。要讲字段内容时必须用真实文字；不要全片只有占位横线。
- **卡片组**：常用 2–4 个。交替黑白能分层，但只给当前重点上紫色。
- **关系图**：细线、清楚端点、圆角节点；线从相关节点出发，不能凭空生长到无关位置。
- **选区**：淡紫矩形底，保持文字可读；选框、光标、身份标签可以组合，但每次只强调一个操作区域。
- **字幕**：参考中有略窄、略斜的白字黑底胶囊；用户认可的短样用粗直黑体。选一种保持一致，不为模仿斜体牺牲中文质量。
- **卡通人物**：参考使用 3D 卡通讲解人物，适合开场、章节提醒和总结。不是必要素材，不擅自克隆作者形象或声音；缺少合适人物时用图解完成。

## 运动基调

动作清楚、起止干净、缓出为主。以下均为建议范围，按语速和画面密度调整。

| 动作 | 时长 / 缓动起点 |
|---|---|
| 卡片入场 | 0.35–0.6 秒，`power3.out` / `expo.out` |
| 相邻对象错峰 | 0.08–0.18 秒；口播逐项点名时直接服从对应时间 |
| 小状态更新 | 0.18–0.35 秒，`power2.out` |
| 多卡归并、连续重排 | 0.45–0.7 秒，`power3.inOut` |
| 背景退焦与前景提取 | 0.4–0.65 秒，`power2.inOut` |
| 线条、荧光笔 | 0.3–0.55 秒；端点与对象出现同步 |
| 录屏推近 / 拉回 | 0.45–0.85 秒，`power2.inOut` |
| 普通稳定镜头 | 常为 3–7 秒，内部按语义变化；不是硬性切镜间隔 |
| 结论阅读 | 至少能完整读完，常约 1–2 秒；长句更久 |

小幅上移、缩放、透明度常组合使用。弹性回弹只偶尔用于明确确认，不把所有卡片做成弹簧。运动模糊只在快速位移期间使用，静止后必须清晰。

## 口播怎样驱动画面

把一段话分为对象、动作、结果三个阶段。例如：

| 口播 | 可见动作 |
|---|---|
| “资料、问题、记录、进度” | 四个对象按提及顺序建立，当前对象略抬起 |
| “以前要反复整理” | 总览稳定，旧状态标题切入 |
| “现在一次完成” | 同一组对象收拢，结果卡展开 |
| “团队还能接着用” | 结果从旧容器拆出，团队窗口与人群接入 |
| “信息不再停在一个人的聊天里” | 背景退焦，前景提取一句结论 |

这是一种组合示例，新题材换成对应对象和逻辑。不能把所有讲解都套成“四个问题 → 一键解决”。

## 长视频结构

可以使用“引子 → 问题模型 → 原理或比较 → 真实操作 → 结果 → 总结”的顺序，但以实际脚本为准。2–4 分钟内容中：

- 章节变化可以使用黑底短页，结束后回到主视觉；不要每句换背景。
- 图解解释关系，录屏证明结果，人物调节讲解气氛。
- 操作段保留点击之前的位置线索和点击之后的状态，剪掉无意义等待。
- 重要约束或结论让画面稳定；新内容出现时通过重排或收起旧说明释放空间。
- 主画面解释内容，字幕保留口播；两者不必逐字重复。

## 音频

本次参考分析没有可靠试听证据，不能宣称原片用了某种 BPM、特定音效或某条音乐。短样保留参考片原有混音用于风格与节奏比较，来源说明见仓库 CREDITS。

新片先确定口播再排动画；按需要给归并、切换、完成添加轻短音效。配乐压在口播下方，保持清晰、不削波。波形、响度和非零音轨仅能证明技术状态，不能替代试听结论。

## 人物口播的综合素材编排

### PPT与透视动效融合偏好（2026-09-19）

用户认可妮懂风格局部样片的透视窗口、步骤推进和焦点切换，并要求融入现有UI。保留黑白紫、无衬线字体和轻阴影；透视用于入场与交接，正文阅读时回正停稳。缺少完整录屏时，主动将PPT、截图和口播拆为可解释的连续状态。详见 [融合规范](ppt-motion-fusion.md)，不把旧样片的黑网格、宋体、口令或原声作为全片默认。

- 按语义选素材：实拍仅在物理动作或场景需要时使用；UI 解释工具与过程，关系图解释概念，大字和词级重点字幕负责强调。
- 用户反馈某类素材不足时，只增补相关段落，不把全片替换成该类素材。
- 人物保持主位。允许真人两侧的 UI 与实拍并存，按需要使用单侧或双侧构图，避开人脸并留出阅读空间。
- 用户用截图或旧成片指定继续优化的版本时，以该版本为基准保留素材配比和主要构图；独立尝试的特效样片不自动并入主片。

### 王哥 GEO 通话样片的明确反馈（2026-09-17）

- 用户要求沿用本 Skill 已确认的黑白紫参考。批评 UI 或字体难看，不代表授权改成深绿、薄荷绿等另一套视觉。
- 被否定的两种方案：大圆头像、点状声波和空泛居中排版的浅紫电话卡；石墨绿、薄荷色状态和暖红按钮的通话面板。不能只在两者之间换颜色。
- 回到参考中的具体内容结构、黑白卡片分层、淡紫选区和 400/700 字重。针对通话重新安排联系对象、状态与开场话术，保持同一对象的连续变化。
- 电话情景素材优先贴合国内业务，可生成不同中国办公场景图，也可使用合适的国内实拍。避免反复复用同一个外国商务打电话片段；素材、UI、字幕与转场按语义混合。

### 后续完整电话课的构图更正（2026-09-17）

- 用户为 `(24).mp4` 最终明确了分段构图：**前 20 秒保留已认可的全屏人物开场与两侧动效；20 秒后人物缩入左下角小圆窗**，右侧为大面积 UI 演示，左栏展示章节编号与主题。不能把小圆窗布局套到开头，也不能让整条片一直保持大人物居中。
- 1920×1080 本次落地值：人物直径约 310 px，圆窗左上 `(34,700)`；主内容横向范围约 `542–1872`。不把源素材自带的大圆形人物原尺寸留在中央。
- 用户提供新构图截图时，人物比例、位置和内容主次以最新截图为准。移动人物后同时重排 UI、照片与字幕，不能只缩小人物而保留左右窄卡和中央空洞。
- 用户指定保留此前开场成片时直接复用已认可的开场内容。若新素材也带有相同开场，核对句子后跳过重复段，再衔接正文；本片采用旧开场 0–20 秒 + 新完整片 20.88 秒后续，完整保留“因为第一通电话……”的起音。


### 销售七问修订反馈（2026-09-19）

- 本片开头为 9.88 秒全屏人物；进入白底讲解后，人物立即固定在左下角小圆窗，沿用用户截图约占画幅宽度 16% 的比例（1920×1080 下约 310 px，x=34、y=700）。不能把源片自带的大圆留在中央，再等到 20 秒才缩小；具体切入时间服从新片的实际开头长度。
- 圆窗进入正文后保持位置与尺寸；将图片与 UI 重排为主内容，避免中央空洞。
- 用户认为开头偏干时，在现有黑白紫视觉内增强与原话相关的客户消息、进度卡住等状态反馈，结合短促提示音和轻推镜，不能仅堆更多大字。

### 王哥 AI 获客整片重做反馈（2026-09-22）

- 用户明确否定“沿用四张图片和原构图，只换卡片外观”作为整体重做。要求整体修改时，应重新安排画面对象与状态变化，同时替换被点名重复的配图。
- 图片题材需要变化：按内容选产品实物、经营现场、技术处理、交付细节等，不连续套用同类会议或围坐电脑的咨询场景。
- 黑白紫是视觉语言，不是固定的“左章节栏 + 右侧标题 + 照片与三行卡”模板。人物仍保持约 310 px 左下角小圆；主内容在大图、软件界面、关系图、手机对话、文档、重点结论间按语义变化。
- 开头要有连续事件和落点，例如产出堆叠、目标追问、顺序纠正。不能只在人物两边挂几张静态标签就称为增强冲击力。

### 王哥 AI 获客连续 UI 修订（2026-09-22）

- 用户继续否定开头和后续，说明仅增加图片题材和切换构图仍未达到本 Skill 的 UI 参考要求。整体重做不能变成各种静态文字页轮换。
- 开头也要使用具备具体内容的软件结构：客户行、搜索框、编辑草稿、制作时间线或可拖动的顺序列表。口播中的动作应让这些对象发生可见变化，避免空窗口与悬挂标签。
- 正文让同一对象贯穿操作：原列表筛选重排、选中行展开详情、原问题进入草稿、原案例进入交付与人工核对。切换章节时可以换应用场景，章内不要每句话重新建一整张卡。
- 截图不能只检查稳定态，还要抽查筛选、展开、移动和归并的中间状态；检查文字裁切、点击位置、移出对象残留和字幕间距。

### 王哥开场素材与合成动效反馈（2026-09-22）

- 用户仍认为纯 UI 开场像 PPT，明确要求补情景素材与 AE 风格动效。此要求适用于开头，不代表把整片改成实拍或取消正文连续 UI。
- 开头可以用与口播一一对应的国内业务情景图片，配透视入场、局部推进、短扫光、批量缩略图、急停和反向回收。真人面部保持清楚，动作服务“找客户、写文案、做视频、顺序反了”等具体词。
- 避免只换图片而保留整齐排列的静态卡片；也不重新加入此前被否定的紫色环绕轨道。素材段、重点字幕与简短结论应形成节奏变化。
- HTML/GSAP 合成可以实现 AE 风格，但交付中明确实际工程格式，不宣称是 AE 原生制作。
