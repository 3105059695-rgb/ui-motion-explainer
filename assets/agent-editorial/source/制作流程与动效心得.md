## 2. 历史开头实现：前 15 秒动作表

**本节仅解释已保留的历史实现，不表示开头得到这次认可，也不要求以后照搬。**本次认可参照是 15–300.04 秒正文及后续段落的整体配色、UI 和动态。

| 时间 | 画面发生的事情 | 帮助观众理解什么 |
|---|---|---|
| 0–3.7 秒 | 三款主产品同尺度落位，另外七个标识依次出现，榜单退在后景 | 先知道“比较十款”，同时只看三个主角，避免十个大卡同时抢眼 |
| 3.7–4.7 秒 | 疑问标题替换开场标题，光标与高亮在原卡片间移动 | 选择发生在已经认识的对象上，不必重新理解一屏 |
| 4.7–7.9 秒 | 产品卡缩小下移，各自对应的官方界面向上展开 | 看清产品与界面的所属关系；这里展示官方材料，不冒充现场实操 |
| 7.9–8.4 秒 | 界面收拢，原卡片缩为右侧候选标识，后景榜单进入主位 | 从“有哪些产品”自然进入“如何排位” |
| 8.4–12.55 秒 | 首尾档出现问号；“少走弯路”随原声盖下 | 保留悬念，暂不提前宣告正文才会揭晓的排名 |
| 12.55–15 秒 | 榜单缩到右上；Codex 从候选队列进入主位，再接正文与真人 | 总览让位给第一个具体对象，观众知道接下来讲谁 |

关键是上一镜的东西成为下一镜的东西。卡片没有凭空消失再换一个无关转场，而是缩小、腾位、展开、归队、接棒。这种可追踪的关系兼顾速度和清楚。

主动作之间有轻重：落位用短弹性，空间迁移用平滑加减速，界面展开错开约 0.16 秒，高潮之后留阅读时间。前景、退焦榜单、阴影和少量运动残影产生层次，避免一直旋转或全画面同时运动。

本版视觉色值在 `film.js:4`：黑 `#0B0B0F`、白 `#FFFFFF`、强调紫 `#8750FF`，辅助灰用于退后。**这套颜色与正文 UI 外观也是用户此次明确喜欢的部分，后续需要一并参考，不能只保留动作。**继续读取正式 Skill 与本工程认可记录，按新稿编排具体镜头；开头三卡、排行榜和 15 秒长度不因这次正文认可而成为固定模板。

## 4. 制作顺序与省时间的办法

1. **先固定原声时钟。** 通读原稿，再把内容分为章节与语义事件。本片 `timing.json` 保存 12 段和每段 cues；画面随话走，评级在说到时才落位。产品评价来自用户稿件，不把它包装成独立客观测评。
2. **找对材料再写镜头。** 产品标识、官方界面和解释示意分开；截图只放大与当前句子有关的区域。代码中 Codex 材料明确标“官方 CLI 示例”，不把它叫成桌面客户端实录。
3. **先写事件链。** 每句确定主角、发生的动作、结果和下一句接什么。正文按当前产品与口播聚焦材料、解释过程，再在原声说到时落下评级。其他主题可以是问题→处理→结果，没必要都排榜。前述开头的“比较对象→对应材料→候选归队→总览→第一款”只是历史实现。
4. **复用播放器和合成层。** `prepare_media.py` 从原视频提取音频及人物帧；`film.js` 用 `floor(t*25)+1` 找原帧。正文动画为 50 fps，真人来自 25 fps，未声称补出真人新动作。字幕最后合成，原声不剪句、不变速、不重配。
5. **先看动作交接，再渲染修改区间。** 静帧检查遮挡与文字，短片检查速度、节奏和音效。只改开头时，不重新制作五分钟正文。本次 15 秒恰好是旧片关键帧，复制之后 14,252 帧的视频码流即可。
6. **交付留可追溯证据。** 成片之外保留源码、音效事件、时序、素材和检查结果；技术通过与审美认可分别记录，不让审查文件取代实际制作。

音频保护在 `revise_opening_audio.py` 中有明确断言：新开头减去新增音效后等于原始 PCM，15 秒以后与旧混音逐采样一致。只为帧网格补齐尾部极短静音；原声增益不变，不做压缩或 EQ。成片 AAC 是有损编码，上述 PCM 等同性针对混音母版。

## 5. 如何预览与另存渲染

环境复用现有 Python 的 Playwright、Pillow、NumPy，FFmpeg/ffprobe 在 PATH，编码使用 NVIDIA `h264_nvenc`。渲染器指向已有 Chromium：
`C:/Users/山有扶苏/AppData/Local/ms-playwright/chromium-1234/chrome-win64/chrome.exe`。

以下 PowerShell 命令只写新的输出位置；先执行公共变量，再任选短片或整片。已有缓存、字体、产品资产要保留；无需重跑 `prepare_media.py`。渲染器内部会覆盖同目录 `chunk.mp4`，因此示例先拒绝已存在的输出目录。

```powershell
$py = 'C:/Users/山有扶苏/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe'
$project = 'E:/方木/ten-agents-ranking/project'
```

15 秒画面与带原声样片另存：

```powershell
$out = 'E:/方木/ten-agents-ranking/render/handoff-opening-test'
if (Test-Path -LiteralPath $out) { throw '目录已存在，请换一个新名字' }
& $py -B -X utf8 "$project/render.py" --start 0 --end 15 --out $out
if ($LASTEXITCODE -ne 0) { throw '渲染未成功，请查看 render-check.json' }
ffmpeg -n -i "$out/chunk.mp4" -i "$project/media/audio-mix-v2.wav" -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k -ar 48000 -ac 2 -t 15 -movflags +faststart "$out/开头带声预览.mp4"
```

整片重新渲染另存（仅改开头时不需要执行）：

```powershell
$out = 'E:/方木/ten-agents-ranking/render/handoff-full-test'
if (Test-Path -LiteralPath $out) { throw '目录已存在，请换一个新名字' }
& $py -B -X utf8 "$project/render.py" --start 0 --end 300.04 --out $out

```

实际历史局部合成入口是 `& $py -B -X utf8 "$project/assemble_opening_v2.py"`。它使用写在文件里的固定输入输出，当前正式交付已存在，**再次运行会拒绝覆盖**。它不是可直接反复调用的新版导出命令。后续改开头应复制并调整该脚本的 `OPENING / AUDIO / FINAL / PREVIEW / WORK` 为新版本路径；保留旧片和母版，不绕过保护强行覆盖。
