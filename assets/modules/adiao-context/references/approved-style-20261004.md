更新日期：2026-10-04。依据当前对话中的直接反馈整理；当期用户的新要求优先。本文件记录可延续的审美与制作方法，不把某一期的具体镜头变成固定模板。

## 已确认到哪一步

- Agent「先复述」v2 重剪交付后，用户明确说：“对嘛，这感觉才回来了嘛！”这确认了整体方向：多种真实和生成素材参与叙事、漫画成为镜头、UI 连续变化、人物安全布局。
- 用户随后要求开头加强宣言感，让相关真实产品 logo 集中出现。v3 已交付品牌集结开头，尚未收到对 v3 的明确审美确认。不能把“已导出”“已播放通过”写成“用户已认可”。

## 视觉与镜头

1. **继承 UI 的颜色、字体、质感与运动语言，每期重新设计布局和镜头。** 不把所有内容装进一个固定窗口，不用常驻标题栏、章节导航、卡片轮播替代剪辑。避免“一页内容进来、停住、整页退出”的 PPT 节奏。
2. **每期开头有一个与口播有关的新事件。** 重新安排主物件、出场动作、画面路线、素材顺序和转场机制。冲击力来自明确主题、大幅度尺度变化、精准落点和可辨认的真实素材；不能只把抽象词“Agent”放大，也不能靠乱转、乱飞或遮挡制造热闹。
3. **动作连续、有因果、有停顿。** 让同一个词、文件、图片或界面对象变形、推进、聚焦并进入下一状态。入口→点击→输入→执行→结果让人看得懂；完整输入展示后才出现提交和回复。快动作后给关键信息阅读时间，不能全部慢悠悠，也不能每一帧都在忙乱运动。
4. **人物是明确的主线。** 开头保留人物原比例，优先利用人物右边的空白区；不要为了塞 UI 缩小人物或盖住脸、手势和主字幕。正文按已确认方向把人物放左下小圆窗，位置与尺寸依真实素材重新避让。v2 的 1920×1080、190 像素圆窗只是工程实例，不是所有片子的固定数值。
5. **用白、近黑和局部紫色维持账号语言。** 保证文字对比、层级和留白。紫色用作焦点、状态和局部质感，不把全屏铺成浅紫、灰紫大板块，不用通透玻璃卡片和低对比细字代替设计。用户已经明确看腻旧版泛紫、空白大、信息轻飘的组合。

## 素材与漫画

- **素材多，且每个素材都对得上正在讲的内容。** 讲某个产品就用核实过的真实 logo、界面、官方文档、仓库或操作画面；讲任务、文件、返工、客户沟通，就用能说明这些动作的图片、三维物件或漫画。素材要在画面中有足够尺寸，让观众一眼认出用途。
- **真实素材与生成素材配合。** 真实材料负责产品身份、事实与操作依据，生成图形负责比喻、故事和情绪；不强制一半一半的机械配额，也不能全片只剩自己画的虚构 UI。产品事实不靠生成图证明，真实界面与演示重建需有清楚区分，示意内容标明“示意”或“演示”。
- **相关 logo 可以尽早成为开头的主素材。** Agent 这一期按上下文把“Work 8”“Codestvt”理解为 WorkBuddy、Codex，与豆包 logo 一起使用。这是当期判断，不是永久词语映射。以后按当期内容核对品牌，不能每期开头都复制豆包、WorkBuddy、Codex 三标集结。
- **漫画用来讲故事，不能只当角落装饰。** 在有角色或情境的段落，安排场景全景→手部或文件细节→人物反应→结果的景别变化，也可以让漫画与真实文档互相接续。先对齐口播，再选漫画；不要用无关可爱图填充空白。
- **表情包放在中段的对应情境。** 困惑、返工、惊讶、理解、完成等情绪出现时才使用，跟动作与语义进出。优先用户提供的可爱素材；不要放开头遮挡，不按每隔几秒轮换，不堆在主信息上。

## 声音、参考与完成方式

- 先锁定实际原视频声音与稿件时间线，再做镜头。保留原口播一次、原速，避免两份素材里重复的声音叠加；若需删改口播或另造声音，按当期要求处理。
- 音效落在出现、撞击、聚合、翻转、切换、确认等可见动作上，跟节奏和力度变化；不持续铺满，不盖住人声。画面平滑还要靠连续帧、运动曲线和实际编码播放验证，不能用“50fps”代替肉眼判断。
- 收到参考要先真正看内容与时间点：口播在讲什么、主素材怎么变、镜头如何接、哪些段落停留阅读。抽帧或文件列表本身不等于理解参考；把能借鉴的具体机制与本期语义对应，再融合账号风格。不要抄参考的主题、创作者标识或整段视频冒充自己的素材。
- 交付具体可打开的 MP4，注明完整版与单独开头，给绝对路径和可编辑工程。必要时放 E 盘根目录，避免只报深层文件夹。实际编码文件的画面抽查、音频/时长检查、完整播放记录，以及用户审美认可分别表述；没听过、没看过的部分不说已经完整审过。
