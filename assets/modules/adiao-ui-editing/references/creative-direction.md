# 视觉、镜头与素材决策

本文件把用户反复指出的失败变成制作标准。数字是调参起点，不是固定模板；当期明确要求优先。

## 视觉语言

| 用途 | 起点 | 处理 |
| --- | --- | --- |
| 主画布 | `#FFFFFF` | 白底与必要的近黑画面形成层级，不用全屏泛紫 |
| 主字、深色结构 | `#101112` | 信息清楚、黑白对比充分 |
| 次级背景 | `#F3F4F5` | 用于控件或局部层次，不铺成模糊灰板 |
| 局部浅紫 | `#CDB7F5` | 选区、深底强调和状态；不直接当白底小字 |
| 白底强调紫 | `#7451B8` | 关键词、操作落点、必要连接 |
| 次级字 | `#6F7075` | 只用于来源或次要信息，主体不用细灰字 |
| 中文字体 | Noto Sans SC 或已获授权的清晰无衬线，常规/粗体 | 真正加载、检查字形、包含进工程；不靠系统碰巧有字库 |

这些颜色来自现有 UI Skill 与近期实际工程。统一的是颜色关系、对比和质感，不是紫色面积、标题栏、三列卡片或每期相同布局。logo、截图和照片保留真实品牌色，不统一染紫。

在 1920×1080 画布上，大标题可从 70–90px、主对象文字 34–54px、讲解文字 25–34px、字幕 40–46px 起步；最终按移动端观看尺寸实看。读不清时重新采高分辨率素材或聚焦局部，不只给低清图套一个更大的窗口。

人物原片若已有美颜或高光，不再整体拉亮导致脸、文字、截图过曝。设计 UI 层和人物层分别处理。开头先测人物整个动作范围，再决定右侧素材区；不要以某一帧脸的位置估算整段安全区。

## 开头：明确、精彩、连贯

开头时长服从完整钩子语义和素材，不固定 3 秒、12 秒或 15.16 秒。前段尽早给出真实可识别对象，后段的运动必须承接它。

可选择的变化机制，不能照表逐个拼成统一开场：

| 本期语义 | 可用变化 | 最后让观众看懂 |
| --- | --- | --- |
| 好成果怎么来的 | 实际成果大图出现，透视退回真实应用/仓库入口 | 这是什么工具，结果和入口的关系 |
| 看不懂一个陌生工具 | 官方名称或 logo 引出真实页面，选中正确入口并展开 | 名字、用途和从哪里开始 |
| 很多文件找不到重点 | 真实文件组沿共同方向进入，筛选出目标并展开内容 | 数量有依据，重点明确 |
| 抽象标题解释具体东西 | 短词变成遮罩窗口，真实内容从字形/边界接续展开 | 字和内容是同一个主题 |
| 流程顺序错了 | 一条可读任务链被纠正，最后一项接入真实结果 | 错在哪、如何调整、发生什么 |
| 多个产品协同 | 当期相关官方 logo 按分工集结到一个任务中 | 每个品牌对应什么，不是无意义 logo 墙 |

运动过程要有共同方向或清晰的接力。旋转只在翻面、空间关系、物件交接时使用；不无缘无故换轴、乱转或叠加多个镜头运动。大幅运动后清晰停稳，下一动作从当前对象状态出发。主阅读中心只保留一个；人物仍可自然口播。

“再炫酷一点”优先增强对象变化幅度、真实材料尺度、速度对比和声音落点，不先增加十个发光特效。用户说“太乱”则减少同时争抢的对象、理顺方向；不是把整个开头删成一个静止标题。用户说“太简单”则补语义层次与对象变形，不退回卡片堆叠。

## 什么才算不 PPT

| 用户不接受的画面 | 具体替换方法 |
| --- | --- |
| 一个标题或截图卡着整句不变 | 让同一材料完成定位、选中、聚焦、展开、结果交接；重点文字读完前不要继续飞走 |
| 每句话换一张整页 | 让前一页中的文件/字段/目标进入下一状态，保留位置或身份线索 |
| 纯 UI 虚构窗口，没有真素材 | 补真实官网/仓库/文档或演示，把最有解释力的区域直接放大 |
| 书封代表整份指南，观众看不到内容 | 展示真实项目名称、README、目录与具体段落，必要时先总览再局部 |
| 漫画只是角落贴图 | 用情境→动作细节→角色反应→结果推进，并把漫画对象接回真实 UI |
| 缩略图模糊、全部内容过小 | 重新采集或局部推近，保留必要上下文；不能强塞完整长页面 |
| 每个字都跳、每个对象都弹 | 保留关键短词动作，长字幕稳定；重要结论给阅读时间 |

## 丝滑的实现要点

- 主过渡通常可从 0.35–0.8 秒起步，错峰约 0.04–0.12 秒；按句子节奏调整，不机械套时长。
- 相接动作保持位置、比例、方向连续；不要在每段缓动边界无故急停。强调落点可以停，但停顿有阅读目的。
- 运动模糊只作用于快速运动，停稳立即恢复清晰；人物源帧、字幕和音频时钟不参与多次采样漂移。
- 透视只在短暂入场/交接使用，正文阅读回正；让边框、内容、阴影、遮罩正确分层，检查白矩形、黑边和被裁阴影。
- 同一节点不要由多个动画争抢 transform；用确定性时间轴，回拖到相同时间得到同一画面。
- 长文字避免交叉淡化形成重字、半新半旧错句；使用整行遮罩或重新排版后明确替换。
- 50fps 是近期交付起点，不是流畅证明。逐帧渲染不能靠复制帧伪装流畅；最终编码还要真实播放，区分解码卡顿和动画本身一卡一顿。

## 素材与漫画的使用

为每个重要论点指定可见依据。素材记录最少包含：`ID、实际文件、来源URL/用户附件、取得日期、真实/生成/操作示意、对应口播、片内时间、必要的源内时间与裁切区域`。实际星数、价格、权益和限时活动在本期核实，不沿用旧截图作当前承诺。

优先官方产品页、GitHub 原仓库、官方文档和真实成果；动态网页用实际浏览器采集。截图要能看清项目名、关键字段或按钮。保存来源，必要时标注；归档网页重新渲染、重建 UI、演示账户与真实操作录像分开说明。示意操作不能冒充已经上传、发出、生成、发布或成功获得收益。

漫画围绕正在解释的冲突制作，例如下载了源码却找不到安装包、需求没说清导致返工、找到入口后完成任务。角色一致，构图可以变化；先选情节，再选远景、特写和反应，不规定每段一定四格。用户给的可爱表情包优先于重新生图；九宫格素材挑适当单枚，不直接整张挤进画面。

表情包只在中间对应的困惑、惊讶、理解、庆祝等语义节点出现。轻巧、有参与感、避开信息和人物，不自动定时轮播。素材丰富以解释力判断，不用数量配额或随机换图凑热闹。
