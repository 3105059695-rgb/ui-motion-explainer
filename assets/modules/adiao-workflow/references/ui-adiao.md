# 阿刁视觉与动效规范

依据：本窗口中 WorkBuddy、Fish Audio、豆包工作、Jev、五技能的用户反馈；2026-09-21 补充的阿刁工作流约定。它是 `ui-motion-explainer` 的账号专属补充，不更改其他账号规则。

## 固定视觉底座

| 要素 | 阿刁默认 | 实施要求 |
|---|---|---|
| 画幅 | 横版1920×1080；沿用最近项目50fps | 新用户要求优先，50fps不代表源片拥有更多真实运动细节 |
| 背景 | 白/近白，轻淡紫局部层次 | 不因“炫酷”就切整片黑紫舞台、霓虹、黑网格 |
| 主字 | 近黑 `#17131E`，中文无衬线粗字重 | 实际嵌入字体，导出后看字形，不能伪粗或拉伸字形 |
| 强调色 | 紫色；深紫到明紫的方向性渐变 | 参考 Fish“白菜价”偏好；大数字/关键短语可用，长段正文不用浅紫渐变 |
| 标题字体 | 优先现有 MiSans Semibold；拉丁标题/数字可用 Outfit Bold | 两类字体形成层级，而非每镜随意换字库；产品Logo保持真实字标 |
| 正文/字幕 | MiSans Regular / Semibold；字幕通常40–46px | 按阅读宽度换行，不能通过缩小到难读来塞满句子 |
| 窗口 | Mac式轻外壳，GitHub材料保留可信仓库结构 | 边框与阴影表达层次；不能用假网址和空卡片冒充真实仓库 |
| 品牌 | 开头尽早可识别产品Logo或界面 | 原品牌颜色可保留，如豆包工作蓝Logo；不强行全部染紫 |
| 声音 | 纯口播 | 不添加BGM、转场音效；视觉按口播重音和句子节奏编排 |

颜色是设计起点，并非所有旧视频实测完全相同。实际使用的字体路径、版本和配色要保存到当期工程。

## 人物与素材关系

- 开头人物使用用户所说的“大画面/全身”呈现：保留输入人物视频可见的原始身体范围，不能凭空生成画外肢体或把人物先塞左下角。
- 大人物阶段允许两侧和身后的真实素材换位，脸和关键手势应清楚；前景人物、后方UI、主素材分别建层。不要整个人横移出画作为每期默认转场。
- 正文按语义进入讲解时，人物转为左下角胸像圆圈；最新确认参考为1920×1080中的直径400px、距左/底48px。旧308px不再是默认。圈内脸居中、头肩占满、下缘到胸口，不露桌面。参考坐标见 defaults.json；新源片抽查动作极值后适配裁切。
- 上述尺寸只是未被当期反馈覆盖时的参考。用户要求“人脸小一点”时，分别判断是圆窗占画幅太大，还是圈内裁切太近；先保留已确认的头肩胸比例，再调整整体圆径与材料布局。读取当期 project.json 和最新反馈，不能用旧默认把已经缩小的圆窗又放大。Codex＋WorkBuddy 修订中的320px属于当期实现，见 [历史记录](history.md#codexworkbuddy正文连续动作与小人物2026-09-23)，不视为所有分集的新固定值。
- 素材需要说明口播中的场景。说“职场、生意场”要有相关场景；说PPT、网站、Skill，应看到对应成果/界面/仓库和关键信息。
- 本期真实成果不存在时，可以制作明确标注的示意；不能把示意包装成实际跑通的结果。第三方帖子截图只是来源材料，不自动证明其中速度、价格或收益结论。

## 动效按材料选择

主家族及连续转场的实施要点统一在 [动效配方](motion-recipes.md)，以 [后期流程](post-production.md) 把口播与真实材料匹配后再选择。相同UI不代表相同构图、相同节奏或每期复制五张卡。

## “AE感觉”的可检查定义

这里指动画表现，不承诺使用Adobe After Effects制作。关注透视、前后层级、曲线速度、对象持续性、遮罩交接与合适的运动模糊：

1. 先排稳定画面，再连接状态，静止时字和界面必须清晰。
2. 快动作有明确方向和减速落点；快速移动可做时间采样的运动模糊，不把整张画面长期糊掉。
3. 过渡期间对象有来源、有去处，前一个对象可以收成后一个入口；不只交叉淡入两个不相关的完整页面。
4. 相邻素材通过共同焦点/容器/遮罩接管画面，圆角窗口不是所有素材都必须套的框。
5. 动效必须给口播服务。强调一句话时可以简洁大字，展示成果时让材料主导；不能整片堆字，也不能整片堆素材。

## 本窗口明确否定的方向

- 把“5个Skill”做成孤立大5周围浮几张空泛小卡，或一旁直排五行列表，就当成强开场。
- 一个屏幕许多矩形素材乱撞、随机消失，像消消乐或裁剪拼贴。
- “炫酷”被理解成持续闪烁、廉价特效、无意义3D旋转、整片深色或人物被移走。
- 黑卡/字幕/波形挡字、挡关键操作；只有大字没有对应的图像或视频。
- PPT翻页式全屏切换、稀少素材、正文重复同一外国办公片段。
- 为追求节奏把PPT、网站和真实操作加速到看不懂。
- 只改字体名称，不检查字重、层级、间距、出场方式和最终渲染字形。

## 样片审核

给用户的是带真实人物和口播的可播放开头，而非静态效果图。内部至少看首帧、主信息稳定帧、动作中间帧、品牌识别、字幕安全区。审核长度覆盖完整开头话语，按该片实际时间决定。用户确认后锁定素材版本与时间轴，正文沿用视觉体系，不把其他实验版混入。


## 已确认的正文人物胸像（2026-09-21）
采用 closeup-v2 的脸/肩比例：圆内脸居中、头顶靠近上缘、下缘至胸口，不露桌面或前臂。圆形整体放左下，1920×1080参考直径400、边距48。原声不变。新素材检查头部运动和发顶完整性；源片缺失不能靠放大或填白伪装修复。

## 字体、基础数值和源文件

可复用 [CSS底座](../assets/adiao-ui.css)。其中标题88px、正文36px、字幕44px、窗口圆角24px等是1920×1080的起始值，不是用户逐项指定。按实际文字和画幅调排版，不把CSS现成类当成完整分镜。

已核实可用字体目录：[fonts](LOCAL_ASSET_NOT_DISTRIBUTED)。中文可选 MiSans-Regular.ttf / MiSans-Semibold.ttf，拉丁数字可选 Outfit-Bold.ttf；该目录含来源和许可。字体名是实现选择，用户明确认可的是截图风格，未指定唯一字库。旧 ACTIVE-FONTS-V3.md 与后续实现有差异，不作为所有成片实际字体的证明。

按 ui-motion-explainer 的 [字体子集方法](../../ui-motion-explainer/references/production.md) 收集本期全部可见文本，嵌入 Chinese-regular.woff2 / Chinese-bold.woff2 到 ProjectSans 的400/700映射。ProjectDisplay仅在确实嵌入选定拉丁字体时声明；产品Logo用真实资源。等待字体加载后导出，再看真实输出字形，不能只改font-family就宣称修好了。

正文安全区域起点：人物矩形包络x=48..448、y=632..1032；字幕默认x=500..1856、底距48。该区域只是起点，镜头焦点、鼠标和长字幕仍需检查。开头字幕在大人物上按手势与背景另排，不机械沿用正文位置。

## 方法 Skill 正文的修订反馈（2026-09-22）

- 用户明确否定“风格虽然很新，但与我的 UI 不一样”的正文 v2。回到已确认样例的近白画布、黑白工作对象、局部紫色选区；大量整屏暗紫编辑器与普通电脑截图不能取代这套视觉。素材需要进入有内容的工作对象，再展开、选中、让位或归并。
- 用户再次指出人物总挡住画面。人物位置必须参与原始布局和所有镜头变换；不能只缩小人物，最后叠在已经排完的材料上。本期用户要求小人物，实际使用 320px、左/底48px；为其保留更大的关键内容禁入区 `(24,680)–(424,1060)`。此数值为本期设置，不改其他分集未被用户调整的默认比例。
- 主文字、鼠标、表头和主素材检查最终坐标，重要内容不得进入人物或字幕区。正文讲自媒体时也不要将带大人物的旧片叠入，再与左下人物组成双人脸。
- 用户指出素材反复只有几个。按不同口播动作补对应材料，例如标注、归档、条款核对、预算、资料比较、流程修改、产品拍摄；不再反复使用同一翻书与外国围电脑镜头。素材数不是效果验收，需实际查看内容、记录范围并匹配句子。
