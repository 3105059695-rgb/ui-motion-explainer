# 风格依据与制作决策

## 两套语言，共用一条动作逻辑

前半是编辑式图解：暖白／灰白纸底，大量留白，黑色衬线主标题，铁锈橙只标语义重词。卡片、文档、放大镜和代码窗有细边与柔影。后半切入漫画语言：整屏奶油色或糖果色、粗黑外轮廓、不规则手绘线和象征性角色／物件。它们通过对象和因果接力，不能用“每页换一个模板”代替。

配色随场景取样，不能用一张“暖白”色板覆盖全片。开场 3.8 秒本次采样点的原背景 RGB 为 `(191,189,187)`，V1 为 `(230,232,223)`，已明显偏亮且偏色。其他纸面可从墨黑 `#171614`、铁锈橙 `#BE5A34`、淡奶油 `#FCF5E3` 等近似起点制作，但它们不覆盖实测值。漫画背景按场景挑一个主色；真实软件截图保留自身颜色。数值、风险和代价可用橙红强调，不能为了统一风格改写真实 UI 的状态色。

## 先校准代表片段，再扩展

用户已否定 V1“感觉不太像”。先选覆盖主要语言的 10–25 秒校准片段，可以拼接数个有精确源帧映射的小段，不能只挑最漂亮的静态画面。源片与复刻统一为 544×720、30 fps 的比较坐标，在同一源时间点逐帧查看；至少覆盖入场、动作发生、阅读稳态和转场前中后。

逐帧记录标题的 `x/y/width/height`、主物体边界及占屏比例、基线与留白、相同位置的背景 RGB／渐变、缩略图列数与高低、遮罩起点和过渡覆盖范围。先修背景明度、文字大小与物体位置，再调细缓动，避免在错误构图上只增加弹跳或阴影。

本次测得的 V1 偏差（不是 V2 已修复的证明）：

| 比较项 | 原片 | V1 偏差 |
|---|---|---|
| 3.8 秒开场背景采样 RGB | `(191,189,187)` | `(230,232,223)`，过亮且偏色 |
| 25.8 秒标题边界框 | `x=42..501, y=77..120` | `x=117..426, y=80..109`，标题明显过小 |
| 九宫格主体位置 | 以同帧原片为准 | 整体约下移 80 px |
| 后半高质量网页 | 3 列不同高度的瀑布流 | 错做成等高的大色块 |
| 后半普通网页 | 5 列内容 | 必须保留列数、单元密度与真实纹理 |

这些差异共同改变了“整体气质”。校准结果需展示同时间点对照，并注明仍未恢复的项；技术通过和主观相似度分别报告。在用户认可之前，V2 保持候选精修状态，不能把它固化成已获认可的默认审美。

后半目视近似色板：描边 `#282338`，奶油 `#FFF8DC`、青蓝 `#A9E5F8`、薰衣草 `#E5D6FB`、薄荷 `#C3F5DF`、蜜桃 `#FFD697`、浅粉 `#FBDADE`、柠檬黄 `#FFF29A`、深靛 `#282043`、珊瑚红 `#F65362`。544 像素原宽下，主体外轮廓约 3–5 px，内部线条约 1.5–2.5 px；放大输出时线宽等比例调整。

## 排版和构图

- 默认参照 544×720 逻辑坐标，输出可等比放大。画幅变化时重排对象和字幕区；保持截图自身宽高比。
- 大字是概念锚点，不是整段字幕。中文编辑式标题可用 Noto Serif SC；软件正文用 Noto Sans SC。字体是近似选择，不宣称已识别原字体。
- 标题大小按字形实际边界框比较，不只对齐 CSS `font-size`。相同字号在不同字体下占宽不同，不能为了塞入较小容器而牺牲原片的文字张力。
- 一帧只有一个阅读中心。白底主词与黑色主体之间保留呼吸距离；漫画场景可让主体占画面较大面积，不靠满屏小装饰营造热闹。
- 外部叙事文字、原截图文字、口播字幕分层。标题不可遮住截图需要演示的位置；横向截图可完整放入竖版舞台，再做有意图的局部特写。
- 透视用于进入、交接和换焦点。阅读关键内容时减弱角度和模糊。不能一直漂移，也不能让中文长期斜切难读。

## 运动的“质感”来自因果

- 文档写入之后才提取参考；放大镜扫到卡片后才选中；指令打完后才发生替换；票券进入容器后计数才变化。
- 同一张获选卡保留身份，从九宫格中抬起，成为下一场代码窗的输入。屏幕退焦时仍留在背景，让浮层有来源。
- 进入动作可较快，稳态承担阅读。不要把所有弹簧设成同一节奏；小提示只需轻回弹，数字变化需能看清起点与终点。
- 圆形 iris 从当前语义对象附近长出，黑描边随圆边推进，下一场从圆内露出。中心、颜色和结束物体由本句决定，不固定每场正中心同款圆。
- iris 内必须真实渲染下一场的图形与动画，外部仍保留继续运动的上一场。半径扩到画面对角线尺度后才移除 mask 和圆边；纯色圆盖满再硬切不具备参考里的“下一世界在圆中出现”。原片所见扩展常在约 0.25–0.4 秒内完成，实际新片按语义调整。
- 动效必须由 frame/fps 决定。随机票券、点缀和粒子使用固定种子；回拖到同一帧应得到同一结果。

## 不应继承的部分

- 12.1–13.533 秒的暗弱“坏结果”卡是参考里的反例，不是此技能的主风格。
- 参考里的模型名称、价格倍数、百分比与结论属于原片文案。新主题的数值必须来自用户或可信证据，示意值要说明。
- 曲面屏幕只出现在特定软件镜头。持续鱼眼、摩尔纹、暗角不是本片的统一视觉语言。
- 真人房间、复杂 3D 桌面、钱包原模型和原声音都是素材问题，不能凭几个几何形状就称精确恢复。

## 后半细节

漫画浏览器保留同一粗描边外壳，内容区域滚动，评价章或表情贴在外侧；不要把真实网站的内部也全画成空框。高质量网页保留 3 列不同高度瀑布流，普通网页保留 5 列密集单元；缩略图中的图片、文字块与色彩分布一起构成质感，不能全部替换成同尺寸色块。可用从用户视频独立裁切的内容纹理承载信息，再由代码控制外壳、排布、镜头和运动；来源与重建部分要分别标明。

手机胜出、上传完成、机器人能力增长等场景，装饰对应具体状态，出现后继续保留。例如机器人先落稳，再增长刻度，再落学士帽，最后出现灯泡。

放射线与少量星点让稳态有活力，中心跟随主物体；全屏高饱和细粒子会破坏原片的阅读层级。脚下椭圆影可约为主体宽 45%、高 10–16 px、透明度 0.12，角色不是写实金属或玻璃材质。
