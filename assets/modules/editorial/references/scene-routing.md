# 按语义选择场景

先确定“这句话需要观众看懂什么变化”，再选视觉机制。下表是参考派生的选择依据，不要求每支片全部使用，也不代表每个机制都是单独的 Composition。

| 内容语义 | 合适机制 | 保持连续的对象 | 主要落点 |
|---|---|---|---|
| 从多份材料提炼一个方法 | 三份参考汇聚成成果 | 参考卡、汇聚线、产物 | 最后一条线抵达后产物清晰 |
| 先看或编写脚本 | 文档卡与局部输入／强调 | 同一纸张、光标、选区 | 重词出现时给短暂阅读 |
| 找到最合适的参考 | 九宫格搜索、放大镜扫描、中心卡抬起 | 已有卡片中的一个 | 先扫中，再边框强调，再抬起 |
| 把资料交给工具执行 | 获选卡接虚线到代码窗 | 同一张卡、连线、代码窗 | 输入抵达后代码／进度开始 |
| 替换内容而保持形式 | 2×2 物件依次翻面替换 | 格子位置、承载平面 | 指令完成后依次响应 |
| 对比原版与新版 | 上下同构舞台、同步时机 | 同位置但不同内容的物件 | 对比差异与同构运动同时可见 |
| 大量资源被消耗 | 票券流入黑盒、计数／进度联动 | 票券、入口、消耗容器 | 接触入口时对应数值变化 |
| 展示相对差异 | 同基线柱图或长短条 | 基线、单位、两类标签 | 两组落定后强调差值 |
| 剩余量减少、工作尚未完成 | 额度环退去与任务条小幅前进 | 圆环和任务进度 | 不能把未完成演成完成 |
| 展示真实软件关键区域 | 截图整体建立→局部聚焦→返回上下文 | 同一截图和焦点坐标 | 关键字段清晰后再加注释 |
| 把已有信息交给另一个工具 | URL／摘录从原页面脱离，新聊天窗在其下展开 | 同一段来源内容 | 来源先被选中／复制，再进入目标 |
| 从反馈决定保留或淘汰 | 评价徽章→卡片灰化→标记退出→网格让位 | 同一网格与受影响卡 | 不能先消失后补理由 |
| 上传资料或完成一次真实任务 | 资源小块飞入目标、进度、完成标记 | 资源、入口和同一进度 | 若是示意需标识，真实结果须有依据 |
| 共享一个可复用资源 | 椭圆关系轨道、多人、同一资源循环 | 资源物体和参与者关系 | 轨道表示关系，不能随机撒图标 |
| 抽象概念需要被看见 | 漫画麦克风、机器人、杯子、星星等隐喻 | 与该语义对应的物件 | 动作解释语义，避免纯装饰 |
| 相邻语义需要换舞台 | 主体引发黑描边圆形 iris | 当前物体的颜色／位置 | 遮罩覆盖与下一场出现连续 |

## 截图项目

一张截图先用 `ScreenshotStage`。默认顺序可以是“整体建立 → 聚焦用户要讲的区域 → 外部标注 → 稳态”，无需凭空编造点击后的页面。只有用户要展示已知操作，并提供足够状态依据时，才拆成可编辑 UI。

焦点坐标使用 456×425 展示面板（含 contain 留白）的归一化位置（0–1），通过 `--focus X Y WIDTH HEIGHT` 或 `public/user-content.json` 的 `focus` 对象设置。先查看截图在面板中的实际位置再选焦点，不要直接把原图坐标当成面板坐标。默认焦点只是示例，不代表自动识别出了按钮。

## 口播项目

为每个语义段记录：时间、对象、起始状态、动作、结束状态、阅读停留。一个较长解释可以延长稳态或展示局部信息，不能只是把入场动画拉慢。字幕可以完整表达句子，画面只需要演示那句话的核心关系。

同一主题优先延续已有对象；出现新的信息来源或观点转折时再换舞台。暖白与漫画的比例由内容决定，不把原片的前后半时长固定套用到每条新片。

## 三种最有辨识度的接力

1. **选择后的卡片**：九宫格的一个单元被放大镜命中，抬起后移到代码窗上方，线再连到代码输入。
2. **来源 URL**：原页面上的 URL 保持同一对象身份，背景退去后 URL 仍留在画面；漫画聊天窗从它下方长出。应使用可跨场定位的前景层，不能先清屏再生成一份相同文字。
3. **语义圆形窗**：从上一句的主体位置露出下一句的物体，扩展时两个场景都继续动画。前一个杯子、问号或角色决定下一次圆心，避免机械统一转场。
