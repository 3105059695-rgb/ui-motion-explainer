# 横屏 AI 软件演示视觉规范

用户于 2026-09-27 确认：16:9 横屏；Codex、豆包、WorkBuddy 的软件操作；Collect UI 的精致界面质感；开场强冲击，正文清楚，关键结果再强调。参考现有 ui-motion-explainer 的连续对象变化、黑白紫和口播驱动机制。

## 画面

- 默认 1920×1080。主体安全区 x=100–1820、y=100–930；字幕另占底部 100 px。单次只有一个阅读中心。
- 参考图为竖屏或 4:3 时，按横屏重排窗口与操作区域，扩展画布留白和连接线；不把整张参考缩到中央，也不横向拉伸字体。完整软件窗、局部操作特写和结果推近按内容交替。
- 外部包装：背景 #F7F8FA、主字 #17191F、次字 #717684、结构线 #E5E7EC、强调 #8061C7、浅选区 #EEE8FB。品牌 UI 按真实依据保留自己的配色，不整屏强制染紫。
- 正文使用随包 Noto Sans SC，数值与英文大标题可用 Outfit。主操作文字 28–36 px，标题 54–76 px，说明 24–30 px；仅非关键信息可低至 20 px。
- 外壳圆角 24–34 px，控件圆角 12–18 px；柔和阴影。留白和结构先于发光。背景可以轻微景深，正文停稳后必须清晰。

## 运动

- 同一对象跨状态持续存在；光标定位 → 操作 → 控件反馈 → 内容变化 → 阅读停留。
- 小反馈通常 0.18–0.35 秒，布局重排 0.45–0.8 秒，镜头推进 0.6–1.0 秒。时间是制作起点，最终由口播或字幕时间决定。
- 开场可用空间展开、对焦、遮罩、短扫光；内容区域阅读时回正。结果出现时只强化一次。
- 光标落点和控件一致；拖拽对象跟随光标；状态更新不得早于触发；关键文本停留到读完。
- 工作流菜单、活动列表与节点配置要保留上下文：打开浮层后原节点仍在；展开列表时下面各行连续让位；切换页签时保留同一个外壳。出现失败或待授权状态时先解释它，不自动跳成成功。
- 禁止整段用静态卡片轮换替代软件操作；避免同时飞入多层字幕、窗口、粒子；不强制每几秒切一次镜头。
- 每个模板提供可定位时间轴，回拖也能恢复正确状态；不使用随机数或系统时钟决定导出帧。

## 参考和真实性

Collect UI 是多个作者和风格的作品集合，并非一个统一主题。参考具体作品的布局和交互机制；来源与复刻状态记录在 coverage.json，不把同一模板改色算作不同作品已复刻。

真实产品复现要核对来源日期、按钮位置和状态。缺乏当前界面依据时标为「界面示意」；动画不能作为真实执行或真实结果的证据。模板示例数据可替换，不能伪造实际产品能力。
