# 按口播选动作

## 从剪辑任务找动作

打开[动作分类目录](<动作目录.html>)，或把[完整 Markdown 目录](<动作目录.md>)交给剪辑窗口。先选“这句话需要观众看到什么变化”，再选具体动作。每条只计入一个主分类；勾选“含跨类参考”能看到别的分类里也用到这一下的镜头。可以叠加参考片、使用形式和关键词，也可以直接点原编号预览和选用。

例如，要让三条说法按口播顺序消失，进“字幕、关键词与清单”找划除。要看三方各自跑了多久，进“对比、测评与做选择”找比较耗时。[Fred JEV 的 41 段](<动作目录.html?collection=fred-jev-41>)按原片时间排，可点开每个编号的演示，或选择自己持有的原片按时码对照。

在本目录下可用以下命令读取分类。新增动作的 `motion.json` 可写 `"directory": "paired"` 指定二级分类。省略时，有原编号的变体沿用原动作主分类，独立动作按名称与含义匹配，含义难以判断的进入“新入库待细分”。用 `classify` 调整后，网页和 Markdown 同步使用新分类。

```powershell
python -B -X utf8 .\入库.py directory
python -B -X utf8 .\入库.py directory paired --related
python -B -X utf8 .\入库.py directory fred-jev-41
python -B -X utf8 .\入库.py search 聚光 --folder paired
python -B -X utf8 .\入库.py classify M052@J066 strike
```

## 打开原动作库

打开同目录的 [口播动作库](index.html)。首页优先展示已从参考片转成定稿 UI 的完整竖屏镜头。可按片名筛选、对照原片时码、替换本期内容，再把选中编号复制给剪辑窗口。「全部动作」可查原有编号。「原片对照表」列出各片已转镜头和待补范围。具体素材槽和用法见[参考片竖屏模板](packs/portraits/来源与使用.md)。

## 在本期镜头中使用

同一动作在 Fred 原片中可以有几种接法。搜原编号（如 `M003`）能找到对应变体。搜完整编号（如 `M003@J088`）会直接找到「三段不同长度的建议依次接箭头」。`J088` 对应原片 94 段盘点中的第 88 镜。预览、选择、复制和离线取用都支持这个完整编号。[按时码找这 41 个动作](<动作目录.html?collection=fred-jev-41>)

1. 记下原句、触发词、同一个对象的起态与结果。例如「我把文件拖到对话框，它就成了附件」，画面需要让观众跟住同一个文件。
2. 搜「附件」找到 **#M061 拖文件进窗口变成附件**。先看文件从哪里来、落在哪里、落下后出现了什么反馈。点「换成本期内容试播」，换上本期文件名。有图片槽的动作可以选择本地图片。
3. 用下面的取用命令把同一套动作带进本期工程。修改导出目录中的 `绑定.js`，打开 `动作.html` 即可离线试播。页面的 `window.ready` 在字体和素材准备好后完成，`window.seek(秒)` 可按本期原声逐帧取画面。工程记录保留稳定编号。
4. 在实际画幅、正常速度和原声下看一遍。动词说到时能看到触发，结果留到看清。重点数字、原图、真实界面和人物来自本期材料。

在动作库目录下运行以下命令。剪辑 Skill 返回的 `confirmed_workflow.motion_library.intake` 是同一工具的完整路径。

```powershell
python -B -X utf8 .\入库.py search 附件
python -B -X utf8 .\入库.py get M061
python -B -X utf8 .\入库.py take M061 --out "D:\本期工程\镜头\文件变附件"
python -B -X utf8 .\入库.py render --shot "D:\本期工程\镜头\文件变附件" --out "D:\本期工程\镜头\附件画面.mp4" --fps 30 --width 1080
```

| 口播要交代什么 | 从哪个动作开始 | 本期要换什么 |
| --- | --- | --- |
| 保留旧句供对照，下方呈现新句 | #M052 先划掉旧句，下方逐字写入新句 | 原句、新句、邻近两行与状态字 |
| 同一份资料能装进哪个容量档 | #M124 同一份材料依次试放不同容量 | 实际容量、各档上限和单位 |
| 竖屏字幕中选中一个词再改写 | #M172 选中文字再替换 | 绑定到既有字幕元素，设置前后文字和替换时刻 |
| 比较同一张图的两次导出 | #087 前后对比滑块 | 在对应绘制函数或本机编辑样片中接入两次实测截屏，保持相同裁切与单位 |

使用 ui-motion-fusion 的逐句工程时可在 `direct -- options` 里直接指定 `--id M061`。照常比较、`choose`、`watch`，再在该镜头试剪表的 `motion` 中填 `inputs`、`assets` 或 `text`。正常的 `trial` 会带着本期原声输出镜头，并在该镜头目录附上可编辑实现。手动 `render` 导出同画幅比例的无声画面，`--seconds` 可指定本期时长。

### 把动作绑到现有 UI

编号 **#001–#240** 保留上游实现与原始分组。**#M001–#M145** 是可改文字、数字及相应素材槽的镜头程序。**#M146–#M192** 是可以驱动现有 DOM 或 SVG 组件的单动作和组合动作。后续剪辑沿用 M 编号继续追加。

下面的代码适用于已加载动作播放器的页面，包括取出的 #M172 镜头。把 `#caption-word` 指向本期竖屏 UI 中已有的文字元素。字号、边框与所在位置继续由该 UI 控制。

```js
await MotionEdition.ready;
const move = MotionEdition.bindExisting('M172', document, {
  node: {selector: '#caption-word'}, before: '待确认', after: '已确认',
  replaceAt: 0.54
}, 2.4);
move.seek(1.5);
```

镜头程序可直接绑定到 Canvas。比如为 #M124 传入 `{inputs: {payloadGB: 32, capacitiesGB: [16, 64, 128], unit: 'GB'}}`，再调用返回对象的 `seek(canvas, 秒)`。有图片槽时可在 `assets` 内按槽名传入同目录图片路径、图片数据地址或已加载的图片对象。每条的默认字段、原始时长、来源与可用槽见 [剪辑索引](catalog.json)。

## 随剪辑持续入库

先按句意查已有动作。同一套动作换名字、图片、数字、画幅或口播时间时，继续使用原编号。出现新的运动方式或交接方式，就把本期实际用过的可复用实现放入工程的 `motion-additions/<动作名>/`，保留 `motion.json` 与它指向的 JS 文件。Skill 会在续剪、试剪或回看等编辑节点收取；也可以随时运行 `python -B -X utf8 .\入库.py collect --project "D:\本期工程"`。

```json
{
  "key": "project-specific-motion-name",
  "name": "动作的中文名称",
  "meaning": "这一变化能帮观众听懂口播里的哪一层意思",
  "uses": ["动作与过程"],
  "engine": "canvas",
  "file": "draw.js",
  "width": 1080,
  "height": 1920,
  "duration": 2.4,
  "inputs": {"label": "本期对象"},
  "mediaSlots": [],
  "timing": ["0.00–0.60 秒，交代对象", "0.60–2.40 秒，触发并停在结果"]
}
```

Canvas 实现导出一个独立的函数表达式，签名为 `function(ctx, width, height, seconds, inputs, assets) { … }`。DOM 取 `engine: "dom"`，函数签名为 `function(stage, binding) { … }`，返回可往返定位的 `{seek(seconds), release()}`。把示例所需的图形、示例底图或本地可携带的资产准备好，让默认参数即可演示动作。完整用途列表见索引的 `groups`。

已经选定库内动作时，`motion.json` 只需写 `{"reuseId":"M061"}`，即可把原编号登记在项目里。取用时如有绑定文件，增加 `--bind 本期绑定.json` 可一并带走本期参数和本地图片。该文件中的 `assets` 路径相对于绑定文件。

工具在本机浏览器检查画面有变化、回拖同一时刻能复现，再追加编号。成功后的 `motion-receipt.json` 记录编号和唯一动作库地址；相同实现再次提交会沿用已有编号。试播失败的候选保留在本期工程中，可以修好后重试。个人选用记录与单镜审美确认由实际项目保存。
