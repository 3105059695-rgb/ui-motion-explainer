# 可移植制作入口：先保风格，再按内容设计

此入口把阿刁系列已经认可的视觉和动作方法做成独立包。无需作者电脑上的其他技能、账号或路径。用户要求本包风格时默认应用；其他账号明确提出的构图、色彩和声音要求优先。

## 收到文案就推进

1. 读取文案和现有媒体，量取时长、分辨率、音轨，查看人物动作极值。用户只要开头就制作开头，要完整片则完成正文、字幕与音画合成。
2. 用本包 `references/series-style.md` 确定视觉底座，再读 `references/opening-design.md` 与 `references/editing-recipes.md`。选适合本期语义的开场，不能把示例的时间轴当作每期固定模板。
3. 按 `references/asset-discovery.md` 自己寻找和查看官方材料，缺少操作录像时重建有内容的 UI 并标注示意。不要让用户再去找“这个剪辑风格”。
4. 建立当前工程：`scripts/new_project.py` 可复制独立运行底座。代理根据实际口播修改 `project.json`、画面和时间轴。底座只是可运行起点；只改标题或把整段脚本塞进一张卡，不是完成作品。
5. `scripts/render_portable.py` 输出 MP4 与中间帧；或继续用已验证的 HyperFrames/GSAP 工程。按 `references/delivery-check.md` 检查真实导出，修复后交付。

## 环境与安装

包内 `install.py` 只复制技能；`scripts/bootstrap.py` 单独创建 `.venv`，安装锁定的 Python 渲染依赖和 Chromium。需要 Python 3.10+、可联网的安装环境及能读文件/执行命令的 AI 工具。不会自动获得商业模型、头像、音色或 API 权限；不能承诺仅下载 ZIP 就绕过这些依赖。

渲染优先 PATH 中的 FFmpeg，缺失时使用 imageio-ffmpeg 的二进制。无需 NVIDIA GPU。Chromium 在 Linux 缺系统库时按 Playwright 的报错处理，不能把环境失败说成视频已生成。WorkBuddy 安装目录由客户端实际设置决定，不能编造统一路径；支持显式 `install.py --target <技能目录>/ui-motion-explainer`，或直接读取解压目录的 SKILL.md。

运行命令使用本包创建的 Python：Windows `.venv/Scripts/python.exe`，macOS/Linux `.venv/bin/python`。路径含空格或中文时按使用的 shell 正确引用。

## 开场工程选择

| 可运行工程模式 | 主事件 | 适用范围 |
|---|---|---|
| `desktop` | 双窗口比较 → 点击相册 → 缩略图进入播放器 | 有对比、参考与作品的内容；原版此后接大人物，再进小圆窗正文 |
| `hero` | 人物右侧工作窗口展开 → 文件曲线进入 → 遮罩接管预览 | 人物右侧留白的约10–20秒口播；素材不能盖脸和手 |
| `timeline` | 成果回溯素材 → 文件进入轨道 → 镜头进入结果 | 制作流程、自动化、剪辑工具；与相册式开场实质不同 |
| `body` | 同一工作台输入 → 附件移交 → 展开预览 → 聚焦结果 | 正文持续讲解；不能用标题+列表轮播代替内容 |

本包演示用原创素材与几何人物占位，避免让使用者误用作者的肖像或私有音色。新工程有真实人物就替换占位并检查裁切；没有人物可用纯 UI 版，不能把占位演示当成用户成片。

完整片可以沿用 `desktop → hero → body` 的已确认衔接，也可以因主题另选 `timeline → body` 等路线。用户已给出顺序时严格沿用。不同开场变化的是主事件与对象交接，UI底色、字重和品牌识别不随意漂移。

## 声音

默认沿用用户提供的口播。用户没有要求新增配乐时不添加。用户已经指定保留源 BGM 时保留，在人声段调好关系；不要因为旧账号规范写了“纯口播”而删除这次已认可的 BGM。新人物或配音服务仅在用户授权并配置好时调用；本包没有内置任何人的声音凭证。

## 与原动效库的关系

56项原动效及 X21–X23 保持兼容；这次补的是可运行的开头/正文机制和交付工具，不把四个工程模式伪称为几十种全新已验证特效。高阶场景仍按当前内容设计。发布验证范围见 `docs/portable-verification.md`。
