# AIGC 导演：句意、场景、动作与画风

收到口播剪辑任务时，由 Agent 判断是否需要 AIGC 并完成内部调用，不等用户再说“调用秋芝”或逐镜解释。
本文件管理 AIGC 的选材、资产复用、表演、节奏与画风；[生成接口](anime-video-generation.md)管理请求、费用和下载；[主流程](workflow.md)管理原声、来源与交付。
UI 的字体、配色、窗口和排版读取[当前 UI 方向](style-profiles.md)。AIGC 角色与场景独立选择，不把场景色盘覆盖到 UI。用户指定摄影写实时，按本期明确要求绑定摄影方向，不再要求手绘女孩图；这不改变黑紫 UI，也不表示所有后续视频都改成写实。

## 当前认可依据与范围

- 资产从 [AIGC 注册集](aigc-assets.json)读取：先匹配当前工程、账号及明确选择，再打开实际参考图；不根据文件名猜画风。
- [最新用户纠正](evidence/aigc-reference-scope-20261019.json)：两张人物图与八张场景图只作画风参考。`direct prepare` 将其标为 `style-reference-only`，不自动当首帧、成片素材或固定场景菜单。每期先按口播设计本期人物、空间、道具和动作，再制作对应素材；图片帮助校准柔和手绘、材质和画面可读性。明确项目固定 IP 时才延续其身份，不强制每期使用同一女孩。
- 用户反馈“这些场景图很不错”确认了这组静图方向；它没有同时确认尚未制作的动画、视频节奏或每个细节已经无误。
- 2026-10-15 后续用户已明确认可[女孩完整样片](../assets/approved-girl-sample/output/preview.mp4)的动作、节奏和 UI 衔接；[独立视频确认记录](evidence/girl-agent-sample-approved-20261015.json)及注册集 `approval.subsequent_video_approvals` 会随 `direct prepare` 读取。通用 user-ui 直接以此校准，新口播按语义改编；静图确认和本视频确认分别保留。
- 旧猫、仓鼠、泛三维人物及早期女孩 8 秒样片保留为历史；不能因已有文件而选为当前认可基线。
- 当前项目明确设置优先。女孩不自动覆盖阿刁、方木或另一个项目的 IP；参考中黑色短发人物、橙色品牌形象也不成为用户主角。
- 秋芝原片的“三维卡通”是来源观察，不能覆盖用户后来明确选择的女孩插画画风。当前风格以注册集中的实际图像与认可范围为准。

## 何时使用 AIGC

先通读整篇，结合完整句意、前后因果、人物语气和情绪，写明本段观众需要理解或感受到什么；再决定承载方式。
只有文字时，情绪和时序是待声音校准的判断；没有音频不编造精确对齐时码。

| 本段任务 | 优先画面 | AIGC 的作用与边界 |
| --- | --- | --- |
| 解释工具如何操作、点击哪里、实际输出什么 | 真实录屏、截图与必要的 UI 聚焦 | 可先用隐喻说明“为什么”，但不能替代真实操作证据 |
| 说明负担、协作、交接、学习、组合或回退 | 能看见动作与结果的 AIGC 小事件 | 把抽象关系变成具体人与物，保持原句的主语和因果 |
| 感受疲惫、受阻、释然或犹豫 | 讲述者或连续角色表演 | 由处境触发表情和身体动作，不能仅换一张表情图 |
| 精确比较数字、版本、条件与结构 | 真实数据、代码图形、UI | AIGC 可建立情境；准确文本、图表和标记由后期承担 |
| 表达判断、态度、关键结论或必要停顿 | 保留讲述者、成果或简洁文字 | 无新增理解收益时不插 AIGC |

一个句子可有几个动作，多句话可共享一个连续场景；不按字幕行、关键词或固定间隔换镜头。
不规定每片 AIGC 占比，也不凑齐 8 类场景。只有“好看、和一个词有关”而说不清解释作用的素材不进入制作。

## 从口播变成可见事件

在现有分镜中记录同一份判断，不另建重复任务卡：

1. **原句与承接：** 原文、段落 ID、前句留下的问题、后句需要的结果；有实声才填写实际口播区间。
2. **解释任务：** 本段的主体、对象、关系与情绪；一句话说明为何选人物、真实材料、UI 或 AIGC。
3. **事件：** 谁在什么地方，拿什么，对谁或什么做什么，发生怎样的变化，最终留下什么可见状态。
4. **关键状态：** 初态 → 触发 → 接触／作用 → 结果；人物表情与身体动作随事件改变。
5. **镜头：** 当前主要焦点、需要的景别、进入和退出锚点、口播语义落点；复杂链可拆镜。
6. **资产与状态：** 引用注册集中的角色、场景、道具和原片依据，记录缺少的关键状态及认可／验证范围。

例如“工具都有，但素材还得我来搬”：同一张图从蓝机器产出，女孩取走、送入紫机器，再拉远看多工位负担。
“有机器人在旁边”和“角色一直在工作”均没有证明接管；必须看见执行者交接及原先任务由谁继续完成。
困难句停在困难、解释改善的句子才出现改善，不擅自把“迁移麻烦”演成“一键搬家成功”。

复用的是解释关系、空间与动作结构。只有新口播确实需要这些关系才沿用；换一句话不等于换标签后照搬所有镜头。
场景可扩展为作坊、森林、工位、能力货架、游戏空间等，不再把所有句子安排在同一白桌、同一房间。
同一连续语义段尽量保留场景与道具；切换地点必须提供新信息，不能仅为“丰富”跳到无关空间。

## 先理解口播，再设计本期图，再生成短动作

1. **提取画风。** 查看实际参考，学习柔和手绘、材质细节、角色与环境统一、光线与可读性；不沿用参考的全部人物、道具和布局。
2. **设计本期事件。** 根据句意、因果和情绪确定谁、在哪里、对什么做什么、得到什么结果。人物与场景服务本期内容；若工程已明确固定 IP，则保持其身份。
3. **制作本期关键图。** 将画风参考与内容设计分别写清；制作符合本镜初态、接触或结果的新图。复用制作代码与方法、同工程已适用素材，不为省事反复套用八张例图。
4. **核对关键状态。** 检查人物比例、手与物体接触、焦点大小、结果可读、画风统一。仅有风格参考时不宣称首帧已完成。
5. **I2V 生成。** 使用本期准备的单场景关键图作首帧；允许时以一致结果图作尾帧。风格参考与首尾帧分工明确，九宫格不能整张作为视频首帧。
6. **剪取有效动作。** 从动作实际开始剪到结果可读，接入原时间轴；生成时长不等于上屏时长。
7. **保存本期记录。** 分开记录风格参考、实际首帧、输出素材、提示词、任务 ID、有效入出点与检查状态。若本期明确要求直接沿用某张旧图，写明该需求或当前工程依据；历史画风认可本身不构成直接用图的依据。

沿用已确认画风不需重新询问；按本期内容设计新素材不要求用户逐张审批。只有实际新方向或超出授权的费用按主流程处理。请求状态不确定时查询已知任务，避免重复付费；接口参数按[生成指南](anime-video-generation.md)。

### 提示词必须落到本镜的可见动作

生图描述按“参考分工 → 本镜初态或结果 → 构图与接触 → 固定画风 → 排除身份混入”组织；视频描述按“从哪一状态开始 → 谁先动 → 物件去向 → 接触及结果 → 景别 → 何时结束”组织。
例如森林书箱交接镜，在已检查的单场景图上使用：

> 沿用首帧的同一位棕色长发女孩、白毛衣灰裤、发夹侧别，以及同一个机器人与森林清地。保持细腻柔和的手绘插画质感和原图的头身比例，不改成三维塑料角色。中景同时看见双方双手与书箱。女孩直接将手中的书箱送到机器人面前；机器人双手托稳箱底后，女孩才松手并收回双手。箱子最终由机器人独立持有，书本数量与方向不变。动作自然利落，没有长时间预备、反复递送或摆姿势。结果看清后结束，不额外加新事件。保留下一镜可接工具箱的位置；准确标签由后期添加。

这段只适用于“交付上下文”；遇到过载、打铁或存档，需要重写相应动作，不能只替换物件名。
模型未完成指定动作时以成片为准记录失败；提示词写得完整不证明画面已经实现。

## 视频画风与连续性

通用要求是画法、材质和镜头内部连续。下表中的棕发、发夹和服装仅适用于本期明确沿用该女孩 IP 的情况，不是所有新稿的默认角色要求；场景例图的偏差不反向成为标准。

| 维度 | 保持方式 | 需要修正的漂移 |
| --- | --- | --- |
| 身份 | 同一棕色长发、脸型、大眼、酒红发夹；发夹在角色自身左侧，正脸画面右侧 | 换成原片短发女孩，换脸、发色或发夹无故跳边 |
| 比例 | 原图的大头短身 Q 版比例、短小四肢；近景用机位表现，不拉伸身体 | 成人化、腿越变越长、每镜头头身比例重置 |
| 衣服 | 当前工程为米白针织上衣、灰裤、白鞋；职业围裙等为任务道具 | 无故换粉色睡衣、改主服装或改变同段颜色 |
| 画法 | 沿用原图细腻柔和手绘、发丝层次、柔软阴影与针织细节，场景匹配已认可图 | 厚黑描边、亮塑料皮肤、泛三维玩具、毛绒动物化、写实真人化 |
| 场景 | 保留认可图的层次、生活用途、光源方向；色温随森林、炉火、工位等地点成立 | 所有场景统一暖黄滤镜、无动机闪烁换光、人物像贴上去 |
| 道具 | 一物一功能，颜色和尺寸跨镜稳定；蓝机器、紫机器与产物对应关系可辨 | 交接中变成另一物件、数量突变、凭空出现结果、机器人型号随镜跳变 |
| 运动 | 人、手和物件确实改变状态；自然重心、明确接触与交接，不无故漂浮 | 只有眨眼、发梢漂移和摄影机推拉，手穿物件或动作倒转 |
| 镜头 | 位置、运动方向、视线与物件去向连续；中景交代关系，近景证明变化 | 为炫技反复绕镜、无动机甩镜、遮住关键接触和结果 |

配角和机器人以当前段实际引用图为准。尚未统一的机器人设计先选一个沿用，不把多张场景里的差异宣称为同一已定 IP。
需要改变服装或风格时服从新口播和明确项目要求；变化有原因并被记录，不把历史候选混入默认画风。

## 节奏：动作完成就推进

用户已经指出“很快能完成的动作拖很久”。默认采用清楚、利落的动作节奏，去掉等待、无意义预备、往返和长时间摆姿势。

- 简单取放、递交或指向，可先按约 **1–3 秒有效动作**考虑；一个短因果段可先按约 **3–6 秒**考虑。这是剪辑设计起点，不是固定阈值、生成器参数或原片测量结论。
- 按实际口播重音、动作复杂度与阅读需求调整：看清初态 → 发生变化 → 读清结果，即可切走；不为了凑满 8 秒让角色一直微笑。
- 生成服务即使要求较长素材，也只使用有效区间；不要把服务默认时长当导演节奏。
- 复杂链可拆成“中景交代 → 手与物近景 → 结果／全景”，用同一物件及方向连接。连续性来自因果，不要求一镜到底。
- 一个时刻只给一个主要焦点；接触和状态改变时避免同时上大段字幕或密集 UI，必要的结果和文字要留阅读时间。
- 优先剪掉冗余与重做错误动作，不用全片强行倍速掩盖拖沓；微调速度不得破坏自然运动、接触与原口播时钟。
- 留白用于理解与情绪；结果已经看清却继续无信息微动属于拖延。反过来，快切不能省略证明因果的关键一步。

## 开头、强调与转场

开头顺着原口播选择可见冲突、结果或差异：人被纸箱困住、同工具链由机器人接管、失败后回到同一存档点等。
第一眼应认出主角、对象和发生的问题；不先花数秒慢慢建立无关环境。无留存率数据，不承诺某种开头“效果最好”。

| 手法 | 何时使用 | 保留的理解锚点 |
| --- | --- | --- |
| 推近／聚焦蒙版 | 观众需要看见接触、卡住的位置、缺失或结果 | 先建立对象位置，强调后必要时回到全局 |
| 拉远／俯视 | 单步已懂，需要看见多工具搬运、箱子规模或流程全貌 | 同一人物、物件与位置，新增的是全局关系 |
| 动作／物件匹配 | 从 AIGC 接真实材料、UI，或进入下一镜 | 相同图像、文件、方向、形状或状态承接 |
| 实物遮挡／揭示 | 当前事件本身有纸张、箱子、前景物经过镜头 | 遮挡由动作触发，揭开后仍能追踪任务去向 |
| 场景缩卡／角色旁讲 | 小故事讲明白后，需要准确命名或解释结构 | 保留刚才的结果画面，再出现用户既定 UI |

不逐句套同一缩放或蒙版。新效果必须帮助看清新信息，不能遮挡关键动作；准确中文、数据、标签与界面继续由后期实现。
生成音轨默认不替换原口播；仅在实际检查后按需保留音效，不让模型重念脚本扰乱母带。

## 可用状态与检查

- **静图认可：** 可作为资产方向和构图依据；已知发夹、比例或配角材质偏差保留记录，不能宣称无误。
- **视频技术检查：** 下载、规格和完整解码通过，只证明文件可用。
- **视频表演检查：** 实看身份、画风、动作链、接触、节奏、进入退出；顺序抽帧不能替代正常速度观看。
- **合成检查：** 放回实际口播，核对当前句、动作落点、结果停留及回 UI 的衔接；无音频不得标音画已对齐。
- **用户认可：** 按实际反馈范围单独记录。新生成成功不自动升级为用户喜欢，静图认可不传递成动画认可。

若角色只有微动、动作结局相反、主物件消失、画风明显漂移，先修对应图或镜头，不重做已确认的无关部分。
展示用静图和静图推拉仍可服务明确的静态任务，但不能交作已完成的连续 AIGC 表演。

## 研究来源与真实边界

总研究：秋芝 AIGC 画风拆解（原始资料未随公开包）；回查具体口播与动作时继续读下列记录：
