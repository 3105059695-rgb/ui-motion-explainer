# 第二层 · 账号与项目风格

这一层只决定当前视频的外观、人物身份、接续样片和适用范围。通用制作与授权阶段见[第一层](workflow.md)，选择优先级见[主入口](../SKILL.md)，具体实现见[效果库](library.md)。其他账号不必继承阿刁身份、配色或画风。

## 先确定属于谁，再读取一个档案

| 当前任务 | 读取与接续 |
| --- | --- |
| 明确是阿刁，或工程已标记为阿刁 | [阿刁档案](profiles/adiao.md)：配色、人物条件、最新系列接续及认可范围。其中角色参考只归该账号，不与通用 user-ui 的另一套女孩原图混用 |
| 明确是方木，或工程已标记为方木 | [方木档案](profiles/fangmu.md)：先读本机索引，按制作模式接续。连续 UI 使用已认可 Skill 整片与每期重编排规则；手写白板使用白板基线。Token 历史整片未认可单独保留 |
| `local-only/ui` 内未另指定账号／项目风格，或其他目录要求“我的UI风格”且无冲突设置 | [用户通用档案](profiles/user-ui.md)：自动读取 [Fred 正文方向](fred-ui-direction.md)，并保留 A01 实现与女孩完整样片的 AIGC 动作、画风及衔接。明确账号设置优先 |
| 已有其他账号／工程规范 | 读取该工程的适用档案，不套用上述两个账号；新反馈保存到该账号或项目 |
| 未指定账号 | 优先从当前工程、用户所指样片及相应确认记录定位已有风格；“我的 UI”不自动代表阿刁。没有可确定的基线且外观会实质影响结果时才问一个必要问题，不默默把新参考或组件示例主题变成用户风格 |
| 忠实复刻 | 原片约束决定外观，账号档案只用于用户明确允许替换的部分；差异按[参考复刻模块](reference-replication.md)记录 |

各账号的认可范围与接续授权在对应档案维护。不同 IP 使用各自主人公和素材，不把私有角色／音色搬到通用包。

AIGC 与 UI 分开解析：[AIGC 注册集](aigc-assets.json)维护角色、认可场景和视频确认，`direct prepare` 通过 `context.aigc` 自动提供。当前适用内容以对应档案为准；通用女孩不覆盖阿刁、方木或明确工程。所有账号可复用[AIGC 导演](aigc-directing.md)的方法，角色资产按各自归属使用。工程可用 `aigc_style_id` 或 `aigc.style_set_id` 指定已注册风格；未知或冲突选择保持未确定。

已选参考方向与本机已认可成片分开定位：`reference_directions` 内嵌当前约束、范围和原话，`confirmed_baselines` 保留实际样片。两者都应读取；`user-ui` 的 Fred 方向不是新制作样片，也不是可忽略的历史材料。其他账号可以借方法，不自动继承此账号外观。

## 本机档案与样片定位

[风格注册表](profiles/registry.json)将账号、原址证据和实现入口关联；[定位脚本](../scripts/style_registry.py)只读当前索引，不复制或改写认可状态。从任意目录运行（下面脚本路径需指向本 Skill）：

```powershell
python -X utf8 scripts/style_registry.py list
python -X utf8 scripts/style_registry.py resolve --project <当前工程目录>
python -X utf8 scripts/style_registry.py resolve --project <当前工程目录> --profile fangmu
```

统一命令也可使用 `python -X utf8 scripts/ui.py styles -- list` 或 `styles -- resolve --project <当前工程目录>`；这是导演在同一个 Skill 内部定位资源，用户无需另行调用账号 Skill。

识别顺序为本次明确 `--profile`、最近工程中已声明的账号／档案、最具体的注册工程目录；声明冲突或未知账号不由目录猜测覆盖。返回档案、已认可片段、实现与证据的实际路径和存在性，并保留认可范围；未确认试稿另列。方木从原址 `asset-map.json` 读取，阿刁接续原确认记录与当前项目索引。`local-only/ui` 默认接续 `user-ui` 当前登记的认可基线；公开包的其他无绑定目录使用注册默认 `user-ui`；明确未知或冲突账号仍保持未确定。`full-transfer-sample` 可接续正确档案修订，其自身 UI 仍在排除项中。`requires_visual_comparison` 始终为 true：路径定位不代替查看实际片段，也不证明当前工程已继承风格。

## 档案保存什么

- 配色、字体气质、材质、明暗层次和容器使用条件。
- 人物身份、出现时机、构图条件、角色／场景参考；位置根据实际动态素材测量。
- 账号开头、表情与声音习惯，以及哪些要求仅限某一期。
- 认可样片文件、具体版本／段落、确认原话和范围；负面反馈与未认可版本另列。
- 本期分辨率、帧率、源音轨、坐标等留在项目；不因一条样片认可而升级成所有视频默认。

在已有项目说明记录 `档案名及版本 / 适用范围 / 视觉值 / 人物条件 / 节奏与声音 / 认可片段 / 本期覆盖项`，不新增审批或配置系统。字体选择同处记 `pairing ID / title / body / latin / 字重 / effect / 回退`，实际字体文件与搭配见[字体模块](qiaomu-typography.md)。

用户要求沿用已确认风格时，必须把**实际认可样片及段落、确认范围、可复用视觉实现**落实到上述项目说明，先查看画面再设计。配色字符串、`tokens` 非空、`prepare/check` 通过均不能代替这些依据；若尚未定位到，明确标为“原风格基线待定位”，继续查已有记录，不把刚做的试用稿自行升级为已确认风格。对照内容包括窗口结构、内容密度、字体尺度、明暗层次、材质与运动，不只对照色号。

2026-10-14 的[完整样片反馈](evidence/full-transfer-feedback-20261014.json)已拆分保存：用户认可 AIGC 搭配顺畅，同时指出截图中的 UI 没有继承既有风格。`full-transfer-sample` 的 UI 不可作后续视觉基线；该片的 AIGC 衔接方法可以按口播复用。局部肯定不得被登记成整片或 UI 外观认可。

## 落实与保留

Fusion 创建器可记录 `--profile`，但这不等于渲染器自动换肤；档案是需要落实到代码、布局和素材的导演约束，读取文档不等于模板已自动换色。黑白淡紫、174px 圆窗、暖白橙等只能在对应账号／案例条件下使用，不能跨账号成为全局默认。

各档案的样片、源码和证据保持原认可范围；新增确认接入相同定位流程，不扩成其他账号或新成片自动认可。私人素材、音色 ID 与账户凭据留在原项目；跨机器仍需按[资源映射](module-map.md)检查实际依赖。追溯出处时读[第四层](history.md)，不同时加载多个旧账号入口争夺规则。
