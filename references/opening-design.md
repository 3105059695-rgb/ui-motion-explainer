# 开场设计：统一视觉，每期有自己的主事件

本参考用于制作新一期视频，或用户明确要求重新设计开头时。
沿用已确认的白／近黑／紫色 UI、字体层级、人物位置与口播要求；开场动作由本期内容决定。
保留当前工程已批准的布局与音轨安排，先在既有内容区域内设计变化；确有内容需要时再调整相关对象。
静态图、局部字幕修订、正文修改不触发重做开场；已经批准的开头保持锁定。
更新系列偏好只影响后续适用任务，不自动重剪旧作品或扩大当前交付范围。

## 先找本期真正发生的事

从开头口播提取一个可见变化：什么对象，经过什么操作，变成什么结果。
第一视觉事件就要与内容相关，让观众尽早看到要解释的对象或问题。
标题可以参与构图，但不默认从“标题出现 → 卡片飞入 → 镜头推进”开始。
先确定主视觉事件，再选择镜头、出场顺序和辅助动作；不先拼特效再给它配意义。
只换文字、颜色、图片或移动方向，通常不足以构成新的开场设计。

例如，视频生产流程可以从素材被组织为时间线开始；权限问题可以从操作受阻开始。
同样是工具介绍，也可能从结果回溯来源、从内部结构剖开、从矛盾状态对照开始。
在语义能成立的前提下选择最清楚的一种，不要求每期增加复杂度或强行炫技。

## 对照最近的开场

能取得历史作品时，查看最近 2–3 期的开场及关键衔接；已有分析与记录可以直接复用。
比较的是动态过程，不只看封面或第一个稳定帧。留意这四件事：

| 比较项 | 需要说明的实际差别 |
| --- | --- |
| 主视觉事件 | 本期是组装、剖开、回溯、解锁、归并还是另一种有意义的变化？ |
| 镜头路线 | 是固定视角中的对象变化、沿关系移动、连续穿入细节，还是结果退回全局？ |
| 出场顺序 | 先给结果、来源、冲突还是操作？观众先获得什么信息？ |
| 对象交接 | 哪个对象保持身份，如何进入下一容器或成为下一镜的内容？ |

用一句具体的话记录本期与近期作品的差别；不能只写“更高级”“更有 AE 感”。
若主事件和关键衔接都相同，改一个实质机制，再检查它是否仍解释本期内容。
没有历史样片、只有一期开场或无法查看时，简记可取得范围并继续设计，不补设审批或阻塞制作。
不要求为了比较而重做已批准的开头，也不要求用户建立额外的历史资料表。

## 按语义选择机制

下列是可继续发展的设计方向，**不是一组全部已渲染、已验证的新样片**，也不是必须轮流使用的模板。
每期只选对当前内容有用的机制，可以另创机制；不把整张表按顺序串成固定连招。

| 语义机制 | 适合的内容与可见变化 | 对象如何接入正文 |
| --- | --- | --- |
| 胶片曲线牵引 | 视频或素材流：一条包含真实语义片段的胶片沿曲线铺开，当前片段接管焦点 | 当前片段停稳并成为预览区域，其他片段保留来源关系 |
| 字形开口进入 | 关键词本身能解释内部机制：从字形的负空间或切口露出相关内容 | 开口轮廓匹配下一窗口边界，文字退出后窗口继续存在 |
| 时间线组装 | 自动剪辑、多步骤生产：素材、字幕或音轨按因果进入对应轨道 | 同一时间线成为操作讲解界面，最后结果来自已出现的素材 |
| 翻页追溯或展开 | 文档、报告、版本变化：翻过表面结论，展示它的来源或下一层结构 | 页边、标题或字段持续保留，翻页后停在可读内容上 |
| 受阻后解锁 | 权限、条件、错误纠正：先呈现受阻状态，再让缺失条件到位 | 原受阻对象恢复操作，随后直接展示状态变化与结果 |
| 结果拆回来源 | 汇总、归因、工作流解释：先给一个结果，再拆出构成它的来源与关系 | 镜头沿其中一条关系进入第一步，结果保留为后续回扣 |

胶片曲线、字形开口、时间线组装与翻页曾在 MoneyPrinterTurbo 开场方向中得到认可。
这份认可说明这些动作可以服务该题材，不代表每期都要复用，也不代表其中任意组合都已验证。
复用成功机制时，仍要判断本期内容是否需要它，以及近期作品是否已经使用同样的主事件与衔接。

已有实现可查 [X21–X23 动作说明与工程](motion-lab.md)：
X21 展示来源归并；X22 展示同一窗口连续推镜；X23 展示曲线交接与遮罩展开。
这些是局部机制的实现参考，不能据此声称上表六种开场都已完成渲染验证。

## 把 AE 感落实到运动细节

AE 感指层次、速度与衔接的完成度，不要求全程使用 Adobe After Effects。
默认沿用当前可编辑工程与渲染方案；用户明确指定 Adobe After Effects 或 `.aep` 时，以实际 After Effects 工程制作和交付。
本参考不新增脚本、依赖、审批步骤，也不改变现有 HyperFrames 运行版本。

- **速度曲线**：按动作含义设计起步、加速、减速与停稳。交接可以中段快、落点慢；强调可以短促到位。避免所有元素匀速滑动或同一种弹簧回弹。
- **对象 alpha**：让窗口、纸张、字形等对象拥有正确的透明轮廓；需要独立淡出的内容单独建层。检查透明边缘，避免把不需要的矩形底一同带入。
- **独立阴影**：对象与投影分层控制，随高度、距离和落地改变强度与范围；阴影不变成脏边，也不随正文一起模糊到无法阅读。
- **匹配遮罩**：入口与出口匹配对象轮廓、位置和尺寸；字形开口、窗口边界或纸张裁切应解释下一画面从哪里来，避免用无关黑块盖住接缝。
- **短时运动模糊**：只覆盖快速移动的对象与时段，减速后恢复清晰。慢推镜、停稳文字和字幕保持可读；接入边界见 [运动模糊说明](motion-lab.md#接入运动模糊与时间轴)。
- **停稳可读**：动作到位后给关键对象、字段和结论足够阅读时间，再开始下一交接；不要让移动、变形、读字与切镜挤在同一瞬间。

对象移交时保留能辨认的身份，例如同一文件名、字段、数字、颜色标记或素材片段。
匹配位置只是起点；交接前后的信息也必须一致，不能用另一个对象悄悄替换结果。
翻页、曲线或纵深都应解释空间与信息关系；没有解释作用时用更简单的连接。

## 保留系列的稳定约束

颜色与字体层级沿用 [视觉与节奏](style-system.md)，不因开场换机制而另做一套视觉语言。
保留当前任务已确认的主标题、对象标题、正文和字幕关系，长文字通过排版处理，不靠持续缩字。
字幕与人物占位全程参与构图：从第一帧到交接中间帧、最终停稳帧，都不能遮挡关键对象或操作。
给运动轨迹也留出避让空间，不能只检查物体起点和终点是否避开人物与字幕。
有口播的项目，默认从 0 秒开始连续推进；不为片头动画新增空白前奏、延迟开讲或截断原话。用户明确另定声音编排时遵从本期要求。
动画嵌入口播的自然节奏，必要时简化动作，让第一句也有对应画面。
真实源操作素材默认保持 1× 播放速度；可以在外层取景、推镜和聚焦，不靠加速源操作制造冲击力。

## 轻量记录与实际检查

可以在当期已有的 project 说明中简记“开场概念、与近期的差别、对象如何接入正文”。
形式沿用现有项目习惯，不强制新 schema、独立文件或额外批准流程。
制作视频时查看开场播放及关键中间帧，核对轨迹、遮罩接缝、透明轮廓、阴影、文字停稳与音画连续性。
检查范围服从当前任务：只更新技能文档时复查文字与链接，不额外制作或宣称验证新视频。
区分已实现机制、待尝试设计和实际检查结果；成片可用性以本期真正导出的画面和音轨为准。
