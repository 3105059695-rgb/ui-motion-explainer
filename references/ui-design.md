# 为讲解重建软件界面

当用户想要“像电脑截屏，但更整齐、更好看、更容易看清”的界面时，使用本指南。既支持静态 PNG，也支持有口播的动态 MP4；按请求交付，不因使用本指南自动增加视频。

核心目标：**保留任务的真实结构，重新设计观众看到它的方式。** 用户认可的两种基准分别是「有具体内容的多卡总览」和「对话与团队工作区的并置」。视觉示例见 [UI 展示页](../docs/ui-design.md)。面试、资料只是示例题材，项目管理、分析、教学、创作等任务都可使用。

## 没有电脑素材时的默认做法

收到文案后，直接为缺素材的段落设计 UI，不默认要求用户提供录屏或截图。提取该段的对象、动作和结果，按 [界面选型](ui-patterns.md) 选择合适的画面；工作台、面试卡片或任何现成工程都只是可选参考。

需要观众停下来读时导出静态界面；需要解释过程时制作模拟录屏片段，如输入、搜索、滚动、选择、展开和状态更新，并接入文案的实际时间轴。可以混合使用真实素材、重建 UI 与关系图解。界面类型、布局和动作随内容变化，视觉语言保持统一；不为增加种类而强行换皮。

## 1. 先选择界面的依据

| 模式 | 什么时候用 | 可以调整什么 | 如何呈现 |
|---|---|---|---|
| **原样产品复现** | 讲真实软件的按钮位置、操作路径、具体结果 | 裁去无关桌面；放大当前区域；增加画面外注解 | 保持真实控件名称、位置关系和状态；用真实素材支撑实际操作结论 |
| **基于真实功能的讲解重建** | 功能有依据，需要降低信息密度、讲清工作关系 | 重排布局、精简导航、放大字段、统一容器与颜色 | 在适当位置标为“讲解重建”；说明经过重新排版，不把动画当作已发生的操作记录 |
| **原创示意** | 讲概念、设想流程或制作通用模板，没有特定产品依据 | 自由设计符合任务逻辑的界面、示例数据与状态 | 标为“原创示意”或“界面示意”；不冒充某产品已实现的功能 |

用户给的是风格截图时，从中提取排版和组件习惯；产品事实仍来自当前任务素材。静态截图只能证实可见状态，不能自动证明点击后会发生什么。需要真实操作证据时接入真实录屏，并清楚交代从重建画面进入了实录。

## 2. 从文案或截图整理到设计

1. **拆出工作结构。** 列清当前对象、关键字段、主操作、状态与关系。例如“任务 → 负责人 → 待确认事项”，先保证它们讲得通。
2. **区分内容与外部壳层。** 去掉播放器进度条、桌面任务栏、浏览器冗余标签、无关通知等附带界面。软件中与当前步骤无关的导航可折叠；关键入口、当前选中项和结果去向保留。
3. **选一个阅读中心。** 明确本帧要看哪行、哪个文档段落或哪个变化；把它放大。为它调整列宽和空间，不靠缩小全屏文字塞下原截图。
4. **先排稳定状态。** 总览、局部详情、协作结果分别排清楚，再连接动画。内容少时留白，内容多时分区、展开或换一个镜头。
5. **使用统一层级。** 页面标题 → 工作区标题 → 当前内容 → 辅助元信息，字号和间距逐级递减。背景白、结构近黑、次级区域浅灰；淡紫负责选区与状态，白底紫字使用较深的紫色。
6. **在最终观看尺寸检查。** 重要文字真正可读，表格列边界清楚，阴影不过重，字幕不覆盖当前操作。按 [制作与验收](production.md) 检查实际导出结果。

颜色与字号起点沿用 [视觉与节奏](style-system.md#设计变量)。它们是可调整的设计变量，不是某款软件或原作者的工程测量值。

## 3. 可组合的 UI 组件

按任务选择组件，不要求每一帧凑齐整套。

| 组件 | 最小可读结构 | 重建时的重点 |
|---|---|---|
| 窗口壳 | 顶栏、工作区名称、正文边界 | 细边框、适量圆角和软阴影；系统圆点只提供窗口识别感 |
| 侧栏 | 3–6 个相关分组、一个当前项 | 当前项清楚，其余弱化；折叠无关层级，给正文让出宽度 |
| 工具栏 | 当前位置、视图切换、一个主操作 | 按钮名称与功能一致；图标和标签对齐，减少无关小按钮 |
| 表格 | 表头、3–5 行代表数据、关键字段 | 合理列宽、共同基线、稳定行高；长内容换行或进入详情，不压成小字 |
| 看板 | 2–4 个有意义的状态列、带身份的任务 | 名称和负责人跟随任务移动；列名、数量与状态更新一致 |
| 对话 | 用户请求、可读回复、输出对象、输入区 | 只留解释本步骤需要的对话；结果文档具有独立身份，可以继续进入其他工作区 |
| 文档 | 标题、章节、真实可读重点、次要文字 | 讲到的内容用文字，非关键段可简化；正文在独立视口内滚动 |
| 详情面板 | 当前对象名称、来源行、相关字段与动作 | 从当前对象旁展开；主列表留在原位或平滑让位，选中关系仍可辨认 |
| 搜索 | 固定输入框、查询词、结果列表 | 展示输入、过滤和定位的因果顺序；保留匹配项的原内容 |
| 协作状态 | 角色、选区或身份光标、同步/评论结果 | 让角色确实对应一个操作区域；图示中的在线、完成等状态不冒充真实平台实时状态 |

卡片里应当有与任务有关的内容，例如表格行、问题清单、记录摘要、状态列。小字、头像、图标和标签共同建立软件界面的可信结构；没有解释作用的细节可以省略。

## 4. 把界面做成连续状态

先写 `对象 ID / 前状态 / 触发动作 / 后状态 / 当前焦点`，再选动效。对象 ID 与内容绑定，跨表格、详情、看板和协作面板保持一致。

| 情况 | 连续变化的做法 |
|---|---|
| 表格行打开详情 | 先选中该行，再让列表让位、详情展开；面板标题对应同一个行 ID |
| 表格排序或筛选 | 对象整体移动或退下，行里的名称、状态、负责人一起走；不能只换文字伪装排序 |
| 文档展开 | 保留窗口壳，改变正文遮罩范围或打开相邻面板；文字保持原比例 |
| 从个人产物到协作 | 同一结果移出原容器，团队区接入，再补角色、选区或同步状态 |
| 看板状态推进 | 同一张任务卡进入目标列，相关状态文字随后更新；先后关系看得见 |
| 从总览到关键字段 | 保留来源位置，局部推近、放大或展开；讲完留结果或回到总览 |

主动作跟随口播，辅助反馈在它之后。打开面板不是整屏重新入场；表格仍在、对象仍在、选中关系仍在。避免镜头和窗口内层同时放大同一段文字。可组合动作见 [动效库](effects.md) 和 [口播动作](narration-effects.md)。

## 5. 按请求交付

- **静态界面**：交付目标分辨率的 PNG，以及可编辑源码和相关资产；按需提供总览或详情，不强制制作动画。PNG 应来自完成排版的实际渲染。
- **动态界面**：交付可播放 MP4、可编辑源码、字体与必要资产；有口播时附对应字幕或时间信息。GIF 可用于仓库预览，不替代成片。
- **源码组织**：界面壳层、内容数据、对象 ID、稳定状态与时间轴分开。HTML/CSS/GSAP 可直接复用；使用其他工具时保留同样的分层与状态逻辑。
- **验收重点**：关键文字可读；窗口与字幕无冲突；详情和选中行相符；动画前后对象一致；来源模式标注准确。只报告实际做过的检查。
