# 通读口播与视觉选材

第一层的语义方法；仅口播选材任务读取，制作阶段、母带、来源记录与交付统一见[主流程](workflow.md)。

本指南解决“给一批口播稿，判断哪里需要什么画面、为什么需要、怎样接起来”。适用于各种内容题材；漫画、手机和窗口只是可选表现形式。
为本用户制作口播视频时，同时读取[2026-10-12 B-roll 偏好](broll-preferences.md)。这是两轮人工标注与 49 个问卷选择形成的当前偏好；具体证据按需读[案例](broll-calibration-cases.md)，不要求重答问卷。方法先于 UI 外观，当前项目的明确要求优先。
先判断观众需要理解什么、感受到什么，再选择能补足理解或情绪的素材与过程；配色、字体、转场和运镜随后服从既有风格与表达任务。
用户要求忠实复刻或已经锁定分镜时，以该约束为准；只能在允许范围内选材与补足，不能擅自改成教学片。

语义分段只用于安排画面，口播保护按主流程执行。

AIGC 的具体使用与节奏读取[AIGC 导演](aigc-directing.md)，角色与认可场景读[AIGC 注册集](aigc-assets.json)。先判断整句的理解缺口，再复用或扩展原片中有任务、有道具、有动作结果的场景；不能只按名词生成通用空背景。此分支由统一入口默认提供，不等待用户另行指定。

沿用风格时，从认可片段理解材质为何可信、信息与情绪怎样起伏、对象怎样交接；这些判断应服务新内容。样片中的具体道具、镜头路线、时长和素材类别不成为下一期默认答案。
先提出本期表达想法，再查现有实现。代码、控件与工具可以复用，但不能因为某段实现方便，就把新口播改造成同一套换字画面；也不为证明创新而重剪已认可段落。
本次创作判断的用户反馈见[2026-10-14 原始证据](evidence/creative-judgment-feedback-20261014.json)。继承观看感受的质量，不能把案例外形固化为模板。

## 先读整篇，再拆语义段

1. 批量稿件先分配稳定稿件 ID，保留文件名与版本，分别记录目的、受众和结论；不得把甲稿的案例或素材误配给乙稿。
2. 通读每篇上下文，确认它属于教学、产品展示、人物表达还是其他目的，观众已有多少基础、论点怎样推进、最终希望观众理解或完成什么。
3. 按完整意思划分语义段，标记承接关系；一句话可拆成几个动作，多句话也可共用一个连续场景，不按字幕行机械换镜头。
4. 结合上下文检查观众此刻的疑问：不认识对象、看不懂关系、不知道步骤、缺少依据，还是只需要听人物把话说完。
5. 先确定需要让观众看到的事实或变化，再找素材。不要遇到“科技”就找代码雨、遇到“增长”就找上升箭头。

### 分清句意、段落任务和人物状态

每段先判断：原句表达的事实／动作／关系是什么；前句建立了什么，后句需要什么；这一段承担介绍、操作、解释、对比、举证、情绪、转折或收尾中的什么任务。再听人物的重音、停顿、语气和情绪变化，决定观众此刻应理解或感受到什么。仅有文字时，情绪判断是待声音校准的推测，不编造已听到的表演。

先作“保留人物／加入 B-roll／二者配合”的选择，写一句选择理由；需要演示变化时，再指定对象与初态、可见触发、变化、结果及接续方式，最后选择实现和声音。不要求每句切镜，不把人物当必须被素材覆盖的空白。一个句子可有多个动作，多句可共用一个连续场景；克制停留也可以完成表达。

例如“终于做完了”：教程收尾可以充分展示成果；疲惫后的释然可以用连续漫画演出松手、呼气、后靠；反转前则让庆祝被新消息打断。同一句话随上下文改变选型，不能绑定一个永久模板。

区分两种常被叫作“抽象”的内容：人的情绪与生活状态通常需要人物表演；结构、约束、堵塞、因果和流向适合可运转的机制动画。真实操作本身足够清楚时直接展示，不为了抽象而额外套隐喻。按 2026-10-13 的补充，需要最终动漫表演时走[动漫视频生成](anime-video-generation.md)，让角色动作、表情和镜头连续变化；多动作漫画可作为分镜参考、临时预览或明确选定的漫画表现，详见[偏好规则](broll-preferences.md)。

仅有文本时用“稿件 ID + 段落 ID + 原文短句”定位；不编造秒级时码。有音频后再按实际语音对齐镜头与阅读时间。
稿件中的事实、数字和承诺不因写进画面而自动成为已核实结论；需要证据的表达应保留来源或待核实状态。

## 按理解缺口选择画面

以下是判断示例，不是每稿必须出现的栏目，也不是按关键词触发的固定模板。

| 观众的理解缺口 | 选择理由与画面过程 |
| --- | --- |
| 不认识某个事物、工具或格式 | 先展示它真实的外形、界面、实物或文件，再用短解释说明本段用途，接一次相关操作或产物。熟悉且非关键的名词不必逐个介绍。 |
| 抽象概念没有可感知对象 | 找到具体人物、物件或案例，演出初始状态、发生的动作和结果；用图形关系说明机制时，保持对象与连接含义一致。 |
| 不知道操作怎样完成 | 连续展示输入、关键动作、反馈与输出，保留操作对象；必要时放大关键区域，给观众看清变化的时间。 |
| 听到多个方面却不知道全貌 | 先按原稿准确展示类别和区别，再聚焦当前项；用当前位置提示承接，不让分类总览变成同时阅读的大段文字。 |
| 不明白两种做法的差别 | 使用相同对象、条件与尺度对比，圈出影响结果的差异；纠错要看到错误发生处、修正动作和修正后的结果。 |
| 数字、结果或因果缺少依据 | 展示可核对的来源、统计口径与合适图表，突出当前比较；不补造数据，不把相关性画成确定因果。 |
| 需要感受处境或完成情绪过渡 | 选有具体行为的真实情境、人物反应、环境或明确示意的场景；也可让讲述者停留，不强塞素材打断表达。 |

判断一张素材是否适合，应能说明它让观众理解哪种关系、相信哪个细节，或感受到怎样的处境。只能回答“好看、热闹、和某个词相关”时，重新选材。
解释深度取决于是否影响理解、当前段落的重要性与口播可用时间；不是每个名词都要解释，也不是每句话都要加素材。不强制凑齐所有素材类别或套用固定秒点。

## 选承载方式，再选外观

- **真实视频或录屏**：具体操作教学使用真实界面，关键触发、反馈与结果有真实素材依据；选择与所讲步骤相符的片段。截图可以解释已存在的状态，不伪装为完整实操。
- **截图、实物、文件**：需要辨认对象或阅读细节时使用；必要时局部放大、分区呈现，再与后续动作交接。
- **图表、关系动画**：用于比较、结构、流向和机制；图形编码要对应实际含义，有数据则交代口径与来源。
- **示意情境、漫画生图**：用于把难拍摄或情绪处境演成具体事件；明确选择漫画表现时，同一张分镜素材可包含同角色多个连续动作，拆出动作图，再切换、叠放组成数秒表演；最终动漫视频按当前 B-roll 偏好和生成模块执行。规划起始状态、刺激、动作／表情改变和落定；角色、场景、方向和物件连续。单张静态表情图反复推拉不等于这套连续漫画表达。
- **纯人物或短文字**：适合态度、判断、提问、关键结论及节奏停顿；不要为了“必须有素材”破坏讲述。

同一段可以组合上述方式，但应有先后顺序和明确分工；素材与 UI 可以通过同一个操作、证据或视线自然衔接，不把摄影仅当背景、把组件仅当装饰同时堆满画面。
先写“本段要让观众看懂或感受什么”，需要变化时再写“展示什么变化”，随后决定是否用漫画、拟真 UI、实拍、图形或其他外观。不能因预设模板方便，就把所有内容改成同一种画面。
既有配色、连续运镜、转场、景别和排版能力继续保留；动效应帮助看清发生了什么，而非遮住必要信息。

需要强调关键词、步骤标题或结果数字时，再按[乔木字库与花字](qiaomu-typography.md)选择字体气质、正文搭配与花字效果。字体包装与素材判断分开：字形更漂亮不替代必要的实物、证据或操作过程。

## 素材判断与补足

先查看实际内容、清晰度、版本与对应片段；文件名或封面不能证明适合。跨稿复用同一素材时分别核对语义。来源、真实／示意属性、缺口补足和费用授权按[主流程](workflow.md)记录；缺少操作依据不以泛素材替代。

真实感来自与本段有关的生活细节、合理的行为和自然的光线材质；泛办公室照片、摆拍表情或无关实物不能自动补足。摄影式 AIGC 可用于明确示意的情境，不能冒充真实客户、操作记录或现场证据。
网感体现在当代观众熟悉的阅读方式、具体处境和及时的节奏变化，不等于热词、快切或堆组件。是否使用摄影、AIGC 和复杂动效，由表达收益决定，不规定每片必须出现或占多少。

## 前 5 秒与内容起伏

先看原口播前 5 秒已经提出的主题、问题或承诺，再选择一个可见的主事件：看见成果、看见差异、看见问题发生，或出现与主题有关的悬念。不把这些选项变成每期相同的开场公式。结果画面可在语义允许时先露出，但口播句子不提前，也不把示意当成已实现的成果。

冲击力通过真实可辨认的素材、前后对比、景别变化、对象交接与声音落点建立。检查这 5 秒是否有信息推进、重点是否看得清、观众是否知道为什么继续看；不能以快切数量或音效数量代替判断，也不承诺能保证平台留存率。

正文强弱随内容：关键操作、结果、差异可加强；阅读时可保持静止，必要时才轻推镜或局部高亮，字幕与主体内容始终可读。不要把“无 PPT 感”理解为所有元素持续乱动，也不要把“可读”理解为长时间放一张图不作引导。

## 把段落连成可理解的过程

- 尽量沿用同一个问题、人物、物件、文件或案例，前一步的产物进入下一步，让观众看见因果。
- 一个时刻只有一个主要阅读或动作焦点；口播、字幕、素材细节不能同时争抢注意力。
- 素材出现应对应正在解释的内容。讲操作时保留必要的因果次序；介绍用途、比较工具或解释成品来源时，允许先展示真实结果，再追溯步骤或来源，不移动原口播句子、不补造结果。
- 段落转换交代对象或问题怎样变化；转场可以通过相同物件、内容、动作、方向或状态连续交接。
- 内容的身份与去向连续，不等于必须一镜到底。实际窗口切换、直接定位错误、完整播放后重放关键动作都可用；找控件或阅读时保留位置上下文，不为炫技迷失操作位置。
- 检查时追问：观众此刻看哪里、知道了什么、还缺哪一步。缺少必要过程时补过程，不只补装饰与转场。

## 在工程中保留口播与画面对照

将本文件的判断写入[主流程规定的现有分镜字段](workflow.md)：让制作者能沿原句理解选材理由、对象变化与前后衔接。没有音频先用语义锚点，有音频再按实声对齐。接着默认走[语义导演接入](semantic-directing.md)查适用配方并调用实现，做到当前授权范围内的实际片段，不停在策划稿等待“执行”。

## 跨题材例子

- **办公教学：“字幕和声音没对齐。”** 展示同一句话在音轨与字幕轨上的错位，播放暴露问题，调整后再次播放；观众看到错误与修正，而非只看到“字幕同步”四个字。
- **烹饪讲解：“分两次加入液体。”** 同一只碗中展示第一次加入、搅拌后的状态，再加入剩余部分；实拍或明确示意的近景让观众辨认动作与状态，不用无关美食合集替代。
- **业务复盘：“本月咨询增长，但成交没跟上。”** 用已提供的真实统计分别呈现咨询与成交，再查看同一批记录中的掉落环节；没有数据时只做标注为示意的关系解释，不补造增长比例。
