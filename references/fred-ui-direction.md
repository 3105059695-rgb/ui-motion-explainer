# 公共正文 UI 的当前展示方向 · Fred 参考

适用：`user-ui`、阿刁、方木的普通正文讲解，尤其用户所说的“人物缩小到最左侧，正文展开”阶段。2026-10-19 用户批准统一正文 UI 继承；账号保留人物、声音及布局习惯。真实开头保留原场景，明确白板、忠实复刻及有具体认可依据的旧项目按对应范围处理。历史局部白色浮层认可不等于新正文退回白底淡紫。当前明确要求优先，修改 AIGC 画风不改变这份 UI 合同。

规则的唯一结构化维护处是[用户原话与 direction_contract](evidence/fred-reference-approved-20261015.json)。`styles resolve` 返回独立的 `reference_directions`，`direct prepare` 把其约束正文与必读路径带入当前工程。这里负责说明如何使用证据和已有实现，不另建一套配色或固定模板。

## 怎样接续既有风格

2026-10-16 的最新反馈进一步强调参考片的“黑紫”与炫酷 UI 质感。先查看[direction_contract](evidence/fred-reference-approved-20261015.json) `visual_calibration.anchors` 中的原片，再按 `hierarchy`、`object-continuity` 与 `delivery_review` 执行。此前只强调白画布和少量紫色过于宽泛，独立窗口做出的并排小窗没有抓住这个重点。黑紫的主体分量、字形尺度与空间层次须在实际画面成立；章节和重点可黑底，白底仍是可用舞台，不把整片锁成一种底色。

这次确认补足 A01 的正文展示与连续剪辑语言：材料有来源，位置能追踪，随句意展开、聚焦、比较、更新和收拢。A01 的源码和认可保留，但不能只读旧样片、复制色号，就跳过当前参考。当前外观以合同中原片锚点为依据；不能把黑紫质感弱化为窄黑表头、浅紫细线和一排始终等大的小窗口。

AIGC 原图、场景和完整样片按[风格层](style-profiles.md)独立接续，只复用适用画风与方法；本期明确的写实要求优先，固定 IP 仅限有依据的工程。参考里的汽车或3D男孩不自动成为新主角；正文不因出现抽象名词就强制生成角色镜头。真实操作、文档、比较和机制图能清楚解释时，使用对应载体；人物处境、情绪与具体事件可由连续表演承担。

有人物时为正文重新排版，人物左置和正文动态各有安全区。不要将参考整个16:9缩成右侧小视频；字体与材料需要在实际输出尺寸上读清。无人物制作不添加空人物栏。原片正文大部分没有常驻人物，这里是按用户要求迁移布局。

## 先理解这一条完整链

原片约00:36–01:14：同题输入 → 多个模型结果 → 从选中位置放大一份网页 → 在窗内看局部 → 旧网页缩小让位给对照 → 对照接成主图 → 多例轮播 → 收成缩略图 → 保留旧结果输入修改意见 → 原结果换成修改后。

同一个材料在多句间保持身份，是本次最重要的接续依据。设计时先确定本稿的前态、触发、可见操作、后态和下一句如何接手，再选效果；不是按名词各找一张图。此链仅为学习例子，不要求新稿逐步照搬。

## 不用重述参考也能进入制作

Agent 从实际技能目录运行：

```powershell
python -X utf8 scripts/ui.py styles -- resolve --project <工程> --profile user-ui
python -X utf8 scripts/ui.py direct -- prepare --script <口播.txt> --project <工程> --profile user-ui
python -X utf8 scripts/ui.py study -- read --id F-M04
python -X utf8 scripts/ui.py study -- example --video fred-argon --row F-L150
```

阅读当前档案与 `reference_directions` 的内嵌约束，按本稿选材料、方法、已有实现和缺件。具体秒点、坐标、人物比例和效果参数留在本期工程；参考中约0.4–0.8秒的布局动作不是硬编码标准。动作完成后须有可读的结果状态，不用持续运动填满口播。

有明确账号时选择其档案；陌生目录中用户说“我的UI风格”且无更具体配置时，由 Agent 选择 `user-ui`，不用用户再次指定 Fred。已打开的旧对话在新一轮制作前由 Agent 重读磁盘上的当前入口，不依赖旧上下文中的 Skill 副本。
