# 每条参考视频能教这期什么

正常用法是给这期的口播和已有素材。Skill 先保留原句，在导演简报里写出每段适合借哪条参考、借哪个动作、用本期什么材料执行。可以跨作者组合，也可以在一段中只沿用一个完整设计。所有镜头共用[当前正文的配色、字级和材质](aesthetic-preferences.md)。

## GitHub 单包如何把每条参考用进本期

新电脑可以直接把仓库地址交给 Codex。Agent 读取[根目录入口](../AI-START.md)，在本对话继续制作。正常准备工程时，`capabilities.library.entries` 把全库每条的用途、外观、调用状态和建议原句放进 `director-context.json`。可用完整 ID 查找任一项。库里的方法按本句需要组合，投稿片则逐片安排职责。

例如阿闰的镜头用于同条件横评，比较区里想让原稿与改稿对齐并逐步揭示差异。可以直接从全库选择 `component:compare`，用本期两份稿件制作组件，再把它填进用片表中横评镜头的 `inputs.a`。

```json
{"from_project": {"capability": "component:compare", "project": "原稿与改稿对比"}}
```

创建这个组件用 `ui.py capabilities bind --id component:compare --stage 本期对象.html --spec 对比.json --out 原稿与改稿对比`。其他实现按 `capabilities inspect --id <完整ID>` 返回的入口构建。明确采用某片的某个方法时，`from_project` 同时填该片的 `source_id`。成片工程中的 `reference-render.json` 用独立能力 ID 或“来源 / 能力”记录具体可见帧。[组件对象和时钟](../assets/editing-kit/README.md#绑定本期对象到素材槽)

`videos plan` 按用户提交的全片与独立样段逐条建立用片表。同一原作的多个名字合并；32 个正向来源在每个完整工程都有位置。6 个明确的历史纠错来源随表保留原反馈。公开包内的[逐片执行参数](../assets/reference-edits/recipes.json)直接描述每条参考各自的材料角色、图层、关键帧、移动、揭示或交接。素材可用本期真实媒体，也可以是原设计、方法、FredTalk 或软件预设用本期参数渲染出的动态镜头。

1. 正常的 `direct prepare` 在工程内生成 `reference-cut-plan.json`，指定人物片时连同原声一起带入。也可独立运行 `videos plan --script 稿件.txt --out 用片表.json`。按实际原声填 `duration_frames` 和各镜头的 `start_frame/end_frame`（左闭右开）、原句编号及专属输入。素材路径相对用片表；`in` 是素材自身入点（秒），`focus` 是归一化材料关注位置，`placement` 是人物或实物旁的实测安全矩形。手部交接、真实操作与角色表演需绑定能播放的当前视频。
2. 同一时间可以让两条参考各管一块画面，`rect` 用归一化 `[x,y,宽,高]`。也可以沿用同一个文件、同一件实物或同一人物连接前后镜头。正片长度与段落顺序由稿件决定。旁白填 `narration`，人物底片可填 `base_video`。单独试一段可用 `--preview`，它会列出尚未采用的来源。
3. 运行 `videos compose --plan 用片表.json --out 本期剪辑`。双击生成的 `index.html` 可离线播放。工程包含本期媒体和可编辑时间线。
4. 运行 `videos render --project 本期剪辑 --out 成片.mp4`。渲染器在每帧绘制后记录真的可见的来源及材料，检查缺失、全程遮住的内容以及真实视频入点。成片旁的工程内 `reference-render.json` 记录各来源的最终帧区间和成片摘要。完整覆盖与作品审美需分别核对。

同一镜头也可以组合两条来源的不同能力。例如阿闰横评中的其中一项结果要演示 Codex 的原文检索，在该素材槽填 `{"from_project":{"source_id":"base-codex","capability":"capability:O21","project":"本期原文检索工程"}}`。工程由 `videos use` 返回的实际适配器用本期资料构建。合成时会核实来源与能力，调用原实现渲染，把这次操作嵌进横评；最终另记它实际可见的帧区间。同一入口也支持已绑定的 FredTalk、Prompt Motion、软件预设、正文设计及事件工程。

在没有旧原片的电脑上，用 `videos motion --id <来源ID>` 查看连续帧的分区变化。可加 `--from 秒 --to 秒` 查具体区间；结合历史动作拆解和源实现来确定停顿与变化。保留旧代码的历史样段会标注证据种类。该数据不含原片画面或声音。

## 例如一条讲工具选型的视频

| 这句要说清什么 | 借哪条视频 | 画面怎样接下去 |
| --- | --- | --- |
| “以前我要在三个工具里反复复制同一份资料。” | 女孩手绘「人工搬运」 | 让同一份资料在三个工具之间走一遍。角色接到资料，动作停稳，再切界面里有同一标记的文件。 |
| “我用同一道题测了三款服务。” | 阿闰会员横评 | 留住题目与预算，依次换入三次实测结果。展示完差异再下结论。 |
| “这个细节只有放大原图才能看清。” | Fred 的 Argon 评测 | 在同一窗口里放大刚才那张图，保留来源，讲完回到可比较的位置。 |
| “配置改坏了，可以回滚到上一版。” | 秋芝的 Claude Code 教程 | 镜头留在同一文件同一行，让错误、撤销操作和恢复结果在同一位置可见。 |

这四段可以出现在同一片里。每次交接要让观众认得刚才那份资料、同一道题、同一张图或同一行代码。具体时长跟本期原声走。

## 从来源找到实际实现

新片用 `direct -- prepare`，已有工程用 `direct -- resume` 获取待剪镜头。原句、证据和完整分工存在本期工程内；按真实素材质量调整落点。

下面的命令从安装目录执行。单独查片和写入可编辑的参数文件不需要账户、联网或原片。

```powershell
python -B -X utf8 scripts/ui.py videos list
python -B -X utf8 scripts/ui.py videos match --query "改坏配置后，回滚到上一个版本"
python -B -X utf8 scripts/ui.py videos inspect --id claude
python -B -X utf8 scripts/ui.py videos use --id claude --capability method:Q-C04 --out my-rollback.json
```

最后一条会用已有动作程序创建本期的绑定文件，同时返回对应的构建命令。填入本期元素、前后状态、素材和口播时机后调用该命令。不同条目沿用自己的实现格式，有的使用场景文件，有的操作已有的 HTML 元素。`videos use` 省略 `--out` 时只查看实现与绑定要求。

## 哪些材料能借

| 目录 | 收录和用法 |
| --- | --- |
| `focus` | 逐片整理的全片、手绘原素材、局部样段和有明确反馈的历史试样。可以按片名或来源 ID 找用途。每条保留认可范围，纠错片只供查看。 |
| `prompt-motion` | 每个案例都有单独的标题、适用线索和对应的重建入口。有具体分镜时可以读它的动作顺序。原作、重建和当前稿件各自标识。 |
| `fredtalk` | 按片段查原有动作链和输入对象。例如「保持窗口滚到卖点」和「把几个分论点收成一句」分别服务不同句子。归档项仍可按 ID 查看。 |
| `collect-ui` | 实际留下观察的作品。可看到滑动确认、状态切换、失败定位等动作及对应预设。只有静态图的记录只用于构图。 |
| `discovery` | 历史站点清单里的未观察视频和待核对条目，按媒体身份合并跨分类的重复发现。获得画面前只作定位线索。 |

用 `videos list --collection fredtalk --query 交接` 等命令检索。页尾的 `pages` 是该次查询的总页数。`videos summary` 给出本安装的实际数量。访谈中的 Frame by Frame、Spotify、SaaS 与案例库里的同一作品可从两边找到，认可范围以访谈为准。

### 最容易混用的几条

- **十款 Agent** 提供正文外观以及任务分组、材料展开、跨设备交付等十套设计。整片的前 15 秒在认可范围以外。
- **Fred 三片** 各有分工。Argon 适合追溯生成结果再看细节，JEV 适合把模型、机器与运行条件对应起来，周报适合在多条消息间更换材料并交回上下文。
- **秋芝四片** 分别处理工作流输入汇合、创作资产确认、关系迁移与教程回退。可按方法跳到相应原句、观察时间与镜头编号。
- **微信原参考** 对应 16 种已有动作。讲“卡在谁身上”和讲“资料如何从一个界面过渡到下一个”分别走 R03 与 R05。
- **最早的豆包、Codex、Token 三片** 各自保留原片、拆解页与截取区间。豆包讲任务归并和协作，Codex 讲检索、高亮和新会话交接，Token 讲步骤灰化与关键词提取。
- **竖屏编辑参考** 借清晰截图的特写、分层和返回全貌。**小王子**借实机成果先行的开头，**API 奶茶**借实物交接，**汽车拆解**借同一对象从整体到计量单位。
- **手绘完整样片与三条原素材** 分别登记。人工搬运、Agent 接手和资料交到下游各有不同的动作目的。实体摄影样片只借衔接；阿刁的角色身份限其本人项目。
- **14 秒印刷校样**由本 Skill 制作，需要校对紫色、纸边与字重时再看；本期的剪法从上述来源选择。

公开包自带逐片用法、可公开的证据和生产实现。制作时绑定本期内容。原档案的研究入口见[安装与维护](../docs/install.md)。新增提交片时在原图集和 `references/video-uses.json` 登记来源、认可范围及方法，在 `assets/reference-edits/recipes.json` 写入该片的真实材料角色和动作阶段；对可用原片更新连续运动测量，再运行 `videos check`。新增的正向提交片若缺少了可执行剪法，检查将列出差异。


## 保存一个镜头

下例中的编号、原句 ID、素材位名和版本号都要替换为当前镜头卡返回的值。帧区间为左闭右开，时间按原声确定；路径相对本期工程。允许先存部分材料，之后继续补齐。一个补丁也可同时保存多个已核对的镜头。

```json
{"changes":[{"shot":1,"revision":"镜头卡的 revision","set":{"unit":"U001","start_frame":0,"end_frame":48,"inputs":{"材料位名":{"path":"素材/本期录屏.mp4","in":0.2},"文字位名":{"text":"本期字幕"}}}}]}
```

主时间线用同一补丁的 `master_revision` 和 `master` 更新，例如 `{"master_revision":"卡片的 master_revision","master":{"fps":30,"duration_frames":3600,"narration":"素材/原声.wav"}}`。需保护人物时，在对应材料位用 `placement:[x,y,w,h]` 绑定实测归一化区域。已有实现可用 `from_project:{"project":"子工程","capability":"component:compare"}`。保存入口为 `ui.py direct -- save --project "本期工程" --patch "变更.json"`。若另一窗口已改同一镜头，重新取该镜头的卡片后再合并。
