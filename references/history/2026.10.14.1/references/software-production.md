# 软件操作与交互预设

用于 AI 软件教程、产品操作、桌面与手机协作、工作流和结果展示。先决定用户需要看懂的操作，再选代码；预设名称不能代替本期分镜。

## 真实操作与概念演示的边界

具体操作教学用真实软件界面和实际观察到的过程；镜头可裁切、放大、加外部高亮，保持关键控件、状态和顺序。只有截图时，可以说明截图中真实存在的状态，不能自行补出未观察到的交互和结果并称为实操。

解释概念、逻辑或数据流时可用重绘界面、图形或预设演示，标注“示意／讲解重建”。界面再逼真也不是产品功能证据。未取得真实操作素材时继续采集、使用已有真实素材或说明缺口，不以重绘默默替代具体教学步骤；用户本次明确要求重建演示时按其范围制作并准确标注。

## 把口播转成可见操作

为每个语义段写清五项：当前对象、触发动作、界面反馈、内容变化、可读结果。

| 口播意图 | 应呈现的连续过程 |
| --- | --- |
| 输入一个任务 | 光标进入输入区 → 文本形成 → 提交反馈 → 同一任务开始执行 |
| 查找或筛选 | 保留当前窗口 → 输入条件 → 结果连续收拢 → 定位目标 |
| 展示执行过程 | 同一任务的阶段、日志或节点更新 → 对应产物出现 |
| 解释失败与修复 | 定位失败步骤 → 展开原因 → 修改必要项 → 重新运行或停在待处理状态 |
| 展示成果 | 从任务打开产物 → 选中具体文件 → 预览展开 → 推近关键结论 |
| 桌面转手机 | 桌面任务与手机保持可识别关联 → 手机执行具体操作 → 对应结果反馈 |

有音频时绑定真实语义时间点；只有文字时注明估计时间。不是每句话都需要打字，也不为旁白未描述的功能伪造操作。

## 保留可信的软件结构

- 先核对目标产品、平台、版本和来源日期；同名桌面版、移动版、工作版与普通聊天版不能混用。
- 保留能识别产品的导航、输入、执行和成果结构，再调整镜头与非关键信息密度。
- 只把官方文字说明当成功能依据；按钮位置、栏宽和图标需要看得到的画面依据。
- 概念解释可制作有标识的「界面示意」，保留可替换的图标、截图与内容入口；具体操作仍遵循上面的真实操作边界。
- 外部包装采用当前选定主题，真实产品与手机素材保留自己的颜色；不要整屏染紫。
- 打开浮层后保留原节点，展开列表时下方内容连续让位，切换页签时保留同一外壳。
- 待授权、缺配置或失败就是该段真实末态，不自动改为成功；示意动画不证明实际执行。

[产品依据记录](../../../../../../ai-ui-director/references/product-evidence.md)提供历史观察和待核实项。该记录的旧核查日期不代表当前版本已验证。

## 选择并改造预设

先查[预设用途与来源](../../../../../../ai-ui-director/references/preset-catalog.md)，需要准确 ID、基准时长和代码时再看[注册数据](../../../../../../ai-ui-director/references/presets.json)与[源码目录](../../../../../../ai-ui-director/assets/studio/presets)。

1. 按动作语义选一个主机制，查看它的起始、中间、结束状态及真实可配置参数。
2. 连续软件故事优先在同一场景内保留窗口，不把多个独立预设直接拼成翻页。
3. 替换本期对象、输入、执行步骤和成果；只换标题通常不能改变原流程含义。
4. 对预设没有表达的动作，修改新工程源码；不要在文档中声称新增但不给实现。
5. 节点数量、分支、端口或长文本改变时，同步修改布局、连接线和时间轴。
6. 将新实现与原参考机制分别记载，目录数量和换色数量不等于完成复刻数量。

工作室与参考目录保留于[资源目录](../../../../../../ai-ui-director/assets/studio)。Collect UI 包含多个作者的风格；取其交互机制，不自动继承样例配色与文案。

## 工程与时间映射

具体字段和场景限制见[项目格式](../../../../../../ai-ui-director/references/project-format.md)。复用现有格式，不自行添加导出器尚未支持的字段。

- `clips` 按顺序、连续且无重叠，最后一段结束与项目 `duration` 一致。
- `params.title`、`params.prompt`、`params.result` 只是通用文本；阶段内容、节点和素材可能仍写在对应源码中。
- 场景支持 `params.cues` 时，以该场景 `events()` 和注释的实际键为准，不假定所有场景通用。
- 拉长 `duration` 只会映射内部时间，不会自动把打字、执行和口播对齐。
- 字幕按项目绝对时间，源媒体按自己的固定时钟；局部动画伸缩不应让字幕和人物漂移。
- 音频是工程内相对路径；未接音轨的示范仍是无声示范。
- 新工程使用本地相对素材，字体加载完再采样；不修改原预设来制作用户稿。

小反馈可从 0.18–0.35 秒、布局重排从 0.45–0.8 秒、推镜从 0.6–1.0 秒起步，再按实际语义调整。最终到位后应留足阅读时间，不把这些数值当硬性节拍。

## 接入与针对性检查

由统一入口选择创建和导出路径；本库现有[创建器](../../../../../../ai-ui-director/scripts/new_project.py)与[导出器](../../../../../../ai-ui-director/scripts/render.py)继续按其真实参数使用。

本库接口为 `window.ready()` 与 `window.render(t, masterTime)`；依赖和支持范围见[渲染说明](../../../../../../ai-ui-director/references/rendering.md)。不要把另一引擎的 `seek(t)` 或参数直接套入。尚未实现时间采样模糊的预设，不因主入口支持模糊就宣称自身具备该效果。

软件场景重点复查：

- 光标先到控件再触发，反馈随后发生；拖拽对象、端口与连线同步移动。
- 推镜前后属于同一任务；操作对象没有无因消失或被另一窗口替换。
- 输入、执行和结果内容相互对应，失败与等待状态没有被视觉包装掩盖。
- 最终观看尺寸下能读懂主操作、关键日志和结果；窗口外预览控件不进入成片。
- 回拖到同一时刻能恢复状态；无声预设不能代替本期音画对齐检查。
