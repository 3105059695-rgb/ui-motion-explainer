# 本用户的 B-roll 语义与镜头偏好

校准版本：2026-10-12 / v1。用于本机当前用户的口播剪辑；本期明确要求、工程已确认设置和账号约束优先。方法可以跨题材复用，不能把一次选择变成所有句子的固定模板。

2026-10-13 补充：用户明确要求“需要动漫的时候，真的能做出来动漫的样子”，并要求将秘塔 MiniMax H3 API 接入本 Skill。需要最终动漫表演时，优先按[动漫视频生成](anime-video-generation.md)制作角色动作、表情和镜头连续变化的视频；漫画多动作分镜仍用于规划、临时预览或用户明确选择的漫画表现。此补充调整制作路线，不改变原问卷选择，也不等于已确认某种画风或样片质量。

2026-10-13 实际样片反馈：AIGC 用于辅助理解口播；动作小、只让人物转头微笑的风格展示，不能自动充当解释型 B-roll。按句意允许数秒内的多动作、多镜头和转场，镜头数量与幅度服从解释任务及可读性。执行规则见[动漫多镜头与解释任务](anime-video-generation.md#先明确解释任务再设计动作与多镜头)，[原始反馈](evidence/anime-semantic-feedback-20261013.json)记录该样片需要返工，未记为审美或语义验收通过。

2026-10-13 修订样片确认：用户看完“脑中完整画面 → 画面收拢碎裂 → 只剩夜空／蓝鲸／飞行”后明确说“可以可以，这就是我想要的效果，我需要的是那些抽象的，都要做成这种的，来方便观众理解”。因此，需要 B-roll 帮助解释的抽象口播，当前默认采用这类具象事件驱动的漫画／AIGC 演绎，必要时混合代码控制文字、界面和机制。按每句话设计有语义贡献的动作、镜头和转场，观众能看清过程与结果；具体场景、镜头数和时长随原句变化。本次修订样片的解释效果已获确认，原人物比 V 样片仍是返工案例。样片、参考图路径及确认原话见同一[反馈证据](evidence/anime-semantic-feedback-20261013.json)。

依据是用户两轮逐句标注、50 题中的 49 个已答选择，以及对规律总结的确认和写入 Skill 的明确授权。第 34 题未答；已答情绪题 9/9 选择连续漫画。这里记录的是**文字方案偏好**，未宣称这些方案已有通过的视频样片。完整文字证据见[标注案例](broll-calibration-cases.md)及[自包含问卷数据](evidence/broll-calibration-20261012.json)，不依赖旧聊天、原工程目录或本地问卷服务器。

## 先判句意，再决定载体与动作

按[口播理解与素材选择](script-visual-planning.md)先读整篇，再结合段落目的、前后句和人物情绪分析。逐段回答：

1. 观众此刻需要理解哪个事实、关系或过程，或者感受到什么？
2. 原句在这里承担介绍、举证、操作、对比、解释、情绪、转折还是收尾？前句已经建立什么，下一句需要什么？
3. 人物的语气、重音、停顿和表情提供了什么依据？无音视频则记“待声音校准”，不把想象的情绪写成实听结论。
4. 应保留人物、切 B-roll，还是让二者配合？先写理由，再指定表现方式。态度、判断、停顿或有感染力的人物表演可以保留人物。
5. 对象由什么初态，经什么触发，产生什么变化和结果？它怎样进入下一句？最后才选特效、贴纸、声音和镜头路线。

语义连续可以通过同一对象、问题、人物或结果建立。不要按字幕行、关键词或固定秒数机械换素材。人物与原声的时间保持连续。

| 人的情绪、疲惫、犹豫、释放 | 先设计同角色的连续表演；最终需要动漫时通过 H3 生成动作视频，明确要漫画时使用多动作拆图、切换和叠放 | Q31–33、Q35–40 与 2026-10-13 接入要求；未推断 Q34，不固定画风，不把静图推拉交作动漫 |
| 找控件、解释细节 | 保留界面上下文；局部放大、高亮、适度压暗；全貌→靠近细节 | Q12、Q41、Q49；观众应知道细节位于哪里 |
| 纠错与复看 | 可以直接切回错误步骤再修正；慢放真实操作或完整播放后重放关键变化 | Q44、Q47、Q50；不强制一镜到底，回放不误报为实时过程 |

用户两轮直接标注还确认：歌词可用 Remotion 简洁逐行出现；“浮现／冲到面前”应由代码把文字运动做出来；“脑海的画变成零散词语”可通过脑子→画→对话框→词语的连续变化表达；提示词不断落下、堆积可表现负担。它们是有语境的案例，不是遇到某个词就自动调用的模板。

2026-10-14 新增参考案例：[本地蒸馏 R06](local-video-design-distillation.md)记录了桌面任务中“指导→犹豫→离开→呼回→纠正”的连续角色演出，以及同任务左右对照。可用于解释需要盯着、被动执行与自主判断；继承因果动作，不自动继承原角色或画风。本次是对原参考设计的总体喜爱，未替换此前具体反馈，尤其 Q16 的稳定主体修订方案继续有效。

## 漫画要形成连续表演

用户明确要求“一张图多个动作”，再垫放、切换成几秒多图的动漫效果：

- 先把同一角色的动作序列画进一张分镜／动作素材，再拆出动作图用于剪辑；角色、服装、场景、物件和动作方向保持一致。
- 基本过程是起始状态→刺激发生→动作／表情改变→情绪落定。按语义与实际口播选择动作数量、景别、切换和叠帧，不把“3 秒／4 张图”固化成标准。
- 例如庆祝→读消息→僵住→双手放回桌上；攥手→松拳→呼气→肩膀放下。关键动作应接得上。
- 一张静态人物图持续推拉、几张互不连续的表情图轮播，不等于用户所说的漫画表演。
- 使用 AIGC 动漫路线时保留段落任务与动作逻辑，以角色参考和分镜约束连续视频，再按实际素材重新对齐；生成后的角色动作须实际查看，不能以接口成功或换成真人外观代替表演验收。

## 特效、贴纸与声音怎样选

先写它加强哪一个可见事件或意思：下落／撞击可表现负担；放大可进入一个想法；拖拽／变形可表达传递与损失；高亮可定位修改；停顿可承接情绪。删去某个效果也不影响理解、节奏或情绪时，不默认保留它。

这轮没有确定贴纸素材风格、贴纸频率、全片音效密度、具体运动曲线、漫画画风或 3D 写实程度。Q45 只说明简单点击可以靠镜头和原声表达，不推导为全片无音效。代码、3D、漫画与真实 UI 都是手段，不按某一种出现次数评定好坏。

## 记录与验证范围

把语义分析加入现有分镜／工程对照，不要求用户填任务卡或逐镜批准。至少让下一位制作者能知道：原句锚点与上下文、段落目的、人物情绪及依据、人物／B-roll 选择理由、对象与状态变化、素材来源及属性、动作落词和阅读停留、前后衔接。

文本阶段只核对“解释是否对应原句、是否遗漏语义、是否有素材依据”；实际样片阶段才检查动作连续性、漫画表演、界面反馈、可读性和音画落点。样片可先静音看能否传达核心动作与关系，再结合原口播看节奏；静音不能完整说明身份或抽象含义的镜头，不因此机械判失败。

将技术检查、实际观看／试听、用户文字偏好、具体样片审美认可分别记录。新句子的样片可以检验能否迁移，不因复述已标句子的方案就宣称已学会全部风格。不要求每次都重做 50 题。
