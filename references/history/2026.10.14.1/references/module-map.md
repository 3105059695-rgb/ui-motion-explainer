## 冲突如何处理

| 冲突 | 统一决策 |
| --- | --- |
| 基础黑白紫、director 自有紫灰、宣传片品牌蓝 | 本期要求和工程确认优先，按风格档案选外观；模板色盘不自动接管当前主题 |
| 参考忠实复刻 vs 用户风格融合 | 主入口先分模式；严格复刻保留原片，融合模式保留用户视觉 |
| 编辑式暖白橙／漫画糖果色 vs 账号色盘 | 明确指定对应风格时启用；只复用截图或转场机制时保持本期主题，创建后在独立工程改色与重排 |
| 18秒、20秒、30–35秒、固定开场秒点 | 都是旧示例或模式起点；实际口播决定时长，前 5 秒检查吸引力，不规定整段开头长度 |
| 固定左下人物、400px 圆窗、旧泛紫 CSS | 只读取相关账号新规范并按素材重测；不能做通用 UI 默认 |
| 宣传片避用鼠标 vs UI 点击演示 | 鼠标仅在解释触发时使用；不作为无意义的装饰 |
| HyperFrames/HTML/Remotion/Python 各种接口 | 保留各自协议；共同规范是可重现时间、正确素材与实际导出 |
| 目录数、旧验证、样片批准混在一起 | 按案例区分来源、实现、当前可用、实际验证和用户认可 |
| 旧流程拿到整片任务立即做完 vs 当前样片流程 | 新片先做实际开头和代表段落，确认后完成；本期已确认或明确跳过样片则直接继续 |
| 旧模块用重建演示代替操作 vs 当前真实操作要求 | 具体操作用真实界面，概念和逻辑允许重绘；缺操作依据不能仅贴示意标签绕过 |

## 保持独立的相关能力

- `adiao-series-guide` 与 `adiao-workflow`：动态账号规范、工程指针、音色／人物配置与资产依赖。仅账号匹配时读取，不将私有身份搬入通用包。
- HyperFrames、Remotion、`motion-graphics`、`general-video`、`faceless-explainer`：框架和外部制作工作流。按所需后端使用，不改变全局默认，不自动升级；无产品捕获的工作流不接管真实 UI 演示。
- 网页 UI、`better-ui`、布局／排版／无障碍技能：仍服务交互网站，不在本次 UI 视频整合范围。通用视觉细节已提炼到 [视觉与质感](visual-quality.md)，不级联加载整套网页技能。
- `animator-skill`：生成视频 motion prompt，可按需使用，不替代可定位时间的 UI 工程。
- 插件缓存、`.agents` 的框架副本与历史 `local-only/ui` 源包本次未改动。此次更新的是当前用户实际调用的 `.codex/skills` 安装目录。

## 资源可用性

运行 `python -X utf8 scripts/ui.py status` 查看本机入口和资源。整合采用“统一规则、原库单份保留”，不宣称把所有外部库物理内置到一个文件夹。仅复制主目录到其他电脑时，基础快照与 F 演示可用；director／replica／editorial 的资源需要连同原目录迁移，或清楚标明缺失。编辑式模板的依赖安装与渲染仍由其 Remotion 工程负责。

原有能力的目录计数与详细映射见 [O/X/F 资源索引](coverage.md)。这些目录可能有重叠，不相加成已验证动效数量。
