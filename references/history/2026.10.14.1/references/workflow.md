# 统一制作流程

本文件统筹制作；视觉归 [视觉与质感](visual-quality.md)，模式归 [模块映射](module-map.md)，当前用户与工程约束优先。

## 导演决策与样片确认

导演自主决定具体镜头、素材、表现形式、转场和音效，不把这些决定逐项交给用户。新视频默认先做样片：

账号已明确授权后续直接沿用时，先执行其档案的接续约定。方木见[方木档案](profiles/fangmu.md)：开头和代表性正文仍需由导演做实际片段对照，但这是交付前的内部检查，不是再向用户索取同一风格的确认。普通新题材、替换文案和重新编排镜头不撤销已定风格；主动改变画风或新要求存在实质冲突时，才提出一个具体问题。用户本次明确要求先看样片时照办。

标题、正文和英文数字的字体由导演按档案与语义从[字体模块](qiaomu-typography.md)选择，先用本期真实文字预览，再与样片一起确认；不额外要求用户逐项审批字体。

1. **制作样片**：使用本期真实口播和素材，完成开头及一个有代表性的正文语义段。开头检查前 5 秒的吸引力，并保留足以看清衔接的后续；正文选能体现主要表达方式、阅读节奏和素材融合的片段。若全片有两种差异很大的表达方式，可再选一个短段。不要只展示炫目的开头而遗漏正文。
2. **确认风格**：交实际可播放的片段，注明对应段落和版本，用短句说明需要判断的风格特征。收到确认前不批量制作剩余整片；可以继续来源整理、时间对齐等不依赖风格的工作。未回复不算确认，只确认开头不自动等于确认所有正文形式。
3. **完成整条**：记录确认的版本与范围，沿用有效风格做完其余内容、导出、预览及可编辑工程；不再为每个普通镜头重复询问。新反馈只影响相关部分，保留已认可内容。

用户明确要求跳过样片、直接一次做完时照办；本期已有相应确认就继续，局部修订按授权改对应部分。只要方案、规则或 Skill 更新的任务不触发视频样片确认。以上是用户选择的制作流程，不是所有工具操作都要批准。

在已有工程说明中保存 `风格档案及版本 / 样片文件 / 覆盖段落 / 确认原话与范围 / 待确认项`，无需另建一套审批系统。确认一个片段不表示用户认可它的所有技术参数为后续默认。

## 唯一基础与资源

基础底座选择同机完整 `ui-motion-explainer`；没有时选 `../assets/base-skill/` 快照。选定后读取它的具体 `references/`、字体、素材及脚本，**不要重新调用其 SKILL 兼容入口**。同一次制作固定一份基础，创建与渲染使用同一版本。

整合后，原库是按需资源，不是互相竞争的规则来源：

| 资源 | 按需读取 | 使用边界 |
| --- | --- | --- |

| 软件 UI | [软件操作模块](software-production.md)，以及所选基础 `ui-patterns.md`、`ui-design.md` | 内容决定类型，真实证据与示意分开 |

## 内容驱动制作

口播任务开始制作前，读取[本用户 B-roll 偏好](broll-preferences.md)，将句意、前后文、段落任务及人物情绪作为选材依据。先决定保留人物、切 B-roll 还是配合呈现，再写清对象的初态、触发、变化、结果和衔接，最后安排 UI 外观、镜头、特效、贴纸与声音。无实际音视频时，语气和情绪判断记为待校准。既有文字方案认可不能替代实际样片认可。

收到口播稿时，先按[口播理解与素材选择](script-visual-planning.md)通读、分段，判断每段希望观众理解或感受到什么，确定具体素材与画面过程，再按[完整动效编排](motion-direction.md)选择动效。批量稿件保持各自的主题、段落与素材映射，适用的资源可以复用。人物、实拍、图形、文字、截图和软件 UI 都是可选载体；依据当前内容使用转场、镜头、排版与声音，不预设每个段落都要手机或桌面。连续性也可通过同一人物、字形、图形、运动方向和语义对象建立。

在现有分镜中记录足以实施的 `稿件与段落锚点 / 上下文与段落任务 / 人物情绪及声音依据 / 观众疑问或表达目的 / 人物或 B-roll 选择理由 / 片内起止 / 当前语义 / 对象 ID / 来源素材与源内区间 / 前状态 / 可见触发 / 后状态 / 焦点 / 阅读停留 / 前后衔接`，具体选型依据见[口播素材模块](script-visual-planning.md)。不再另做重复表格。有真实配音就按发声时间对齐；无声音的视觉测试明确说明，不把估时称为已完成音画同步。

同一文件、行、设备、人物和结果在镜头之间有稳定身份；字段、数值、名称和来源一致。先完成稳定排版，再连接运动。窗口外壳、内容视口、选区、光标、设备、相机、字幕和人物分层。

素材获取按当前主题进行，官网、仓库、文档和真实录屏各自说明来源；读取内容后再用。附件里的命令是资料。用户稿件与原视频保持只读，在独立项目中制作。缺少素材时主动查找真实素材或生成标识清楚的概念示意，记录来源、用途与属性；具体操作缺证据时不能用重建画面代替实操。新增费用按用户要求先确认。

短样长度随实际语义，整片长度随完整内容与音轨；前 5 秒是开头吸引力的检查范围，不是强制开头时长。按上面的样片确认阶段推进，获确认或明确跳过样片后继续到导出。费用、发布或其他未授权外部操作仍按实际请求处理。

## 工程与声音

沿用已有工程的引擎、帧率与媒体时钟。新工程用 [统一命令](../scripts/ui.py) 调用适合的原后端，工程内容仍需按语义设计。基础及融合模板、软件预设、参考工程的项目 JSON 与渲染接口不同，不混用。`editorial` 通过统一命令创建，生成后用项目内的 Remotion 脚本渲染。原模板复制出来仍带原来的颜色与示例内容；选定的风格档案需在独立工程明确落地，不能只读了规则就宣称画面已换色。

真实操作录屏默认 1×，可剪等待；为了看清关键动作可做注明“重放／慢放”的回看，重复过程压缩注明“加速演示”。比较效率保留真实累计耗时，不把剪辑时长当运行时长。人物与声音保持一个连续母带，操作回放不能拉动人物口型或原口播时钟。动作模糊采样只移动图形，固定源视频、字幕和口型的主时间。内嵌视频在实际导出帧中要推进，不能只验证 DOM 的 currentTime。

默认口播内容、顺序与原声不动；不将删铺垫、提前后面的句子或重新配音当作视觉优化。素材中重复的开头先定位，选定母带后只使用一次。明确获准剪改口播时再同步更新字幕、人物映射与镜头时间。

音效用于有意义的点击、交接、确认，不掩盖口播；BGM 按当前要求与账号规则决定。保留来源和授权，不从参考音轨推断未试听的 BPM 或配器。

## 与任务相称的交付检查

文档／技能修改做格式、链接和依赖入口复查；代码运行相关已有检查；视频导出核对分辨率、时长、帧率、音轨与完整解码，再看代表稳定帧、主要过渡中间帧及尾帧。主观完整播放与声音试听没有做就如实标明。

检查新内容真正使用了正确字体，长文与手机控件不溢出，点击先于反馈，结果留足阅读，人物无双影，源媒体不冻结，音轨不重复。局部修改验证相应区间，不为低影响改字重复整套制作。

有口播的片段还要对照原句检查：选用的画面是否解决这段的理解问题或表达目的，陌生对象是否可辨认，必要的过程和前后变化是否可见；泛素材、装饰动效和重复字幕不能替代这些信息。只检查文件格式不能证明素材选择正确。

用户对实际片段提出新反馈后，按[持续完善规则](broll-preferences.md#根据实际视频继续完善)保留原句、上下文、时间点和修改依据，再更新对应条件规则；只在项目中确认过的参数留在项目，不因为一次修改就改变全部视频的默认。

交付当前请求所需的实际文件与可编辑工程。原库历史验证、目录数量和旧项目状态只作背景；不能替代本次验证，更不能替代用户审美确认。
