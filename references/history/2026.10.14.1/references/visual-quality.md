# 统一视觉与质感

适用于不同账号与题材的原创／风格融合模式。先按[风格档案](style-profiles.md)确定本期外观；忠实复刻使用原参考视觉值，已有项目优先遵从已确认配置。选择 Remotion 后端本身不等于选择暖白或糖果配色。

统一质感覆盖文字、图形、转场、镜头、人物与实拍合成，也覆盖截图和设备界面。下面的软件与手机细节只在对应画面出现时适用；完整剪辑可以由人物、图形或动态文字主导。

## 用实际样片校准

优先查看当前账号已认可的实际片段，校准字重、层次、材质和运动。需要基础样例时，选用同机 `ui-motion-explainer` 或包内 `assets/base-skill`，固定一个底座，查看 `assets/approved-demo/contact-sheet.jpg`／`preview.mp4` 与 `references/style-system.md`。底座样片不是所有账号的色盘，不复用其面试文案、四卡构图或时长。

黑白淡紫的具体值保存在[阿刁档案](profiles/adiao.md)。其他账号遵循自己的已确认外观；模板 tokens 或历史 CSS 不能悄悄接管本期主题。真实产品素材保留自身颜色。颜色比例根据人物场景和信息层级安排，不把配色名解释成必须铺满某种颜色。

## 从低保真到可信界面

- 使用符合主题的软件结构：窗口、侧栏、当前路径、工具栏、主内容、输入区和结果容器各有职责。手机保留对应系统的状态栏、机身比例、应用结构、键盘和手势条。标题、段落、图标都使用实际内容。
- 字号、字重、行高按阅读顺序分层；使用可随工程交付的中文字体。代码名和元信息降低权重，主要内容在导出尺寸下可读。长内容重新排版或局部聚焦，不挤成小字。
- 标题、重音词和数字可按内容选用[乔木字库与花字](qiaomu-typography.md)中的本地搭配；花字服务强调，正文保留清晰阅读，真实应用内的字体仍以对应界面为准。
- 边距以共同基线和视觉对齐确定。嵌套圆角协调，按钮、输入框和图标描边一致；光学位置优先于机械居中。图标用清晰的 SVG／真实资产，避免混用风格和用方块假装应用图标。
- 近黑顶栏／当前项／结果区建立结构，不要求每个元素都变黑。次级分区用中性浅灰，边框轻而清楚；阴影分出层次，范围与距离对应对象位置，不靠大片发光。
- 先判断容器是否必要。大片空黑底在亮人物画面里会显得沉重；可直接利用原背景，用局部小浮层承载信息。删除底板、缩小有效面积与改善层次，比机械把黑底换白更能解决这类问题；深色场景仍可按需使用黑底。
- 截图与视频按最大显示尺寸选择源清晰度，保持等比。窗口变化优先调整遮罩和外部容器，正文避免非等比拉伸。导出为 1080p 不会恢复低清素材细节。

## 连续运动与注意力

同一对象持续：输入框提交后成为同一任务；文件到达新容器后展开对应内容；手机始终保留方向与位置线索。既有状态在过渡中让位，新状态从明确来源进入。

动作起步干脆、减速柔和；强调的变化幅度与语义重要性匹配。阅读阶段仍保留轻推镜或局部高亮，字幕与重要句子保持稳定、清晰；不同时叠加多种循环效果。快速位移可用短运动模糊，清晰读字阶段关闭；弹跳和透视只在需要时使用。

镜头推近当前操作点，其他内容让出注意力；完成后回到总览或交给下一对象。一个镜头与一个窗口内层不要同时独立放大同一内容。不要把每句话都改成新标题卡，也不要只给静态截图缓慢放大就当作完整 UI 交互。

## 内部设计关口

先检查总览、关键操作、最终结果三个稳定状态：颜色比例是否对应样片，字体与素材是否足够清楚，阴影与圆角是否统一，主要区域是否有真实内容；再连接动作。把源时钟和动作检查纳入当前制作，不强制用户多次审批。

用户说“质感差”时，按真实素材细节、结构完整性、字重间距、明暗对比、强调色用量、阴影与中间运动逐项定位。仅换色或加模糊通常不能修正结构问题。通用改进写入本规范，账号特有偏好写入对应档案。
