# 我的 UI 动效剪辑

定位是**通用剪辑导演＋可切换的账号风格档案**。用户给口播和素材，导演负责理解内容、选择素材与表现形式、设计节奏和衔接。转场、运镜、动态排版、图解、人物、实拍、界面演示及参考复刻都是可选能力；某段完全没有 UI 也可以。具体配色和人物位置来自风格档案，不代表所有账号的默认外观。

用户只需调用本技能，菜单名称为 **我的 UI 动效剪辑**，稳定调用标识为 `$ui-motion-fusion`。`ui-motion-explainer`、`ai-ui-director`、`adiao-ui-editing`、`apple-kinetic-promo`、`prompt-motion-replica`、`editorial-ui-motion` 是兼容名称，素材和脚本继续保留在原目录；不再并行加载这些旧入口的完整规则。职责及资源见 [模块与兼容映射](references/module-map.md)，跨对话调用见 [本机全局使用](references/global-use.md)。版本号表示本机统一规则的修订，不表示上游依赖已更新。

## 先确定当前任务

从请求与现有工程识别：要描述／规则、静态图、局部修改、样片还是完整视频；属于原创制作、风格融合还是忠实复刻。只要描述或技能更新就交对应内容；局部修改保留已认可部分。视频制作按下方导演约定推进，不要求任务卡。会实质改变结果且无法从上下文判断的缺口，一次问一个短问题，同时继续独立工作。

规则优先级：**本次明确要求 → 当前工程已确认设置 → 适用账号的最新反馈 → 所选模式 → 旧模板默认值**。

**方木视频先接续已确认基线。** 请求明确属于方木，或工程已标记为方木时，先读[方木风格档案](../../profiles/fangmu.md)及其中的本机样片／实现索引，再选材和建工程。用户已授权下次直接沿用：继承已确认的风格、人物处理与运动方法，按新口播设计内容；不重新询问基础审美，也不从通用模板重做已调好的字幕和动效。最新实现与实际认可范围分别读取，不能把整片导出成功当作整片审美认可。

**口播制作先完成语义判断，再选视觉和动效。** 读取[口播理解与素材选择](references/script-visual-planning.md)及[本用户 B-roll 偏好](references/broll-preferences.md)，结合整段上下文、人物语气与情绪，决定哪里保留人物、哪里加入什么 B-roll、对象怎样变化以及如何衔接。后者是 2026-10-12 两轮标注与 50 题中 49 个已答选择形成的当前默认，不是所有创作者的通用审美；第 34 题未答，不推断。具体案例与未验证项见[标注案例](references/broll-calibration-cases.md)。只换 UI 外观、按关键词配素材或套特效不能替代这一步。

**需要动漫表演时制作连续动作视频。** 2026-10-13 用户要求接入秘塔 MiniMax H3：按[动漫视频生成](references/anime-video-generation.md)设计角色、动作、表情与镜头，用角色参考或首帧生成真实推进的动漫片段，再接入原口播。漫画分镜可作动作设计和临时预览，不自动充当最终动漫成片。已有同角色多动作漫画偏好继续适用于明确选择漫画分镜的语境。仅在需要此类 B-roll 时调用；先核对本次或项目内已授权的生成预算，没有预算则先给具体样片方案及估价，确认后调用。

- **原创／风格融合**：先按[风格档案](references/style-profiles.md)选定账号或本期视觉，参考提供动作、镜头或结构。按内容选人物、实拍、图形、文字和 UI；只有需要时才加入软件窗口或设备。后端和模板不替用户选择主题。
- **忠实复刻**：用户要求照原片、逐帧或保持原风格时，保留原片颜色、字体、画幅、时长和镜头路线；用户指定替换的部分除外。清楚登记差异。
- **继续已有项目**：先核对当前源工程、素材、确认状态与实际导出版本，沿用其有效配置；不因整合技能而重剪、升级引擎或替换母带。

**已蒸馏的本地剪辑参考。** 2026-10-14 用户喜欢的横屏参考已整理为[对象接力与语义演出：16 条剪辑配方](references/local-video-design-distillation.md)。制作新片时，章节交接、文件／卡片重排、总览与细节往返、异常恢复和连续角色比喻可按句意选用；先选解释任务，再选配方，外观仍服从账号档案。不把这次分析当作 16 个已实现预设，也不覆盖已有具体反馈。

## 统一视觉与质感

对高保真制作先读 [视觉与质感标准](references/visual-quality.md)，并查看所选基础的实际样片。

- 颜色、字体气质与人物布局按当前风格档案；黑白淡紫及阿刁布局见[阿刁档案](../../profiles/adiao.md)。真实品牌、手机壁纸和应用保留自身颜色。底板只承担必要功能，先判断容器是否需要，再决定它的颜色和面积。
- 使用可信的软件结构、可读内容、精细图标、合理边距和轻阴影；拒绝泛紫大底、粗糙占位图标与低对比灰紫板块作为高保真交付。
- 同一对象从状态进入下一状态：**对象 → 可见触发 → 状态变化 → 结果 → 阅读停留**。一个段落一个主动作，一个时刻一个阅读中心。窗口保位展开、手机联动、焦点推镜、柔和减速服务于内容。
- 具体操作教学使用真实界面及有依据的真实过程；概念与逻辑允许重绘并标“示意”。真实录屏默认 1×，可剪等待；为看清动作可做注明“重放／慢放”的回看，重复过程压缩注明“加速演示”，不改变实际耗时含义或人物口播时钟。缺少操作证据时记录缺口，不能用拟真动画冒充实操。来源画面、独立实现、技术验证和用户认可分别记录。
- 动画与人物源时钟分离；交接时不双脸、不中断嘴型、不重复声音。人物构图只在相关账号／素材任务中应用。

## 导演工作约定

以下默认来自 2026-10-12 的直接访谈，本次用户明确要求可以覆盖。详细执行见[制作流程](references/workflow.md)。

- **先样片，后整片**：先交实际可播放的开头和代表性正文片段，收到风格确认后完成整条。确认属于具体版本和范围；明确说“跳过样片／一次做完”或已确认本期风格时，按授权继续，不重复审批。未回复不算确认。
- **口播原样**：保留内容、顺序和原声；不通过提前结果句、重排、删掉铺垫或再造声音救开头。视觉修订围绕现有语音设计。
- **前 5 秒要抓人，后续随内容起伏**：在原口播内建立可辨认的主题、结果、差异或悬念；不固定每几秒换卡，也不把正文降成静态幻灯片。
- **阅读仍有克制动势**：结果出现后，用轻推镜或局部高亮引导阅读；文字保持清楚，不用强透视、频闪或反复弹跳抢注意力。
- **素材缺口主动补齐**：找真实素材、生成示意图或制作概念演示，交付说明来源及真实／示意属性。新增费用另行确认；真实产品事实与操作不能凭空补造。
- 持续复用[剪辑习惯与避坑手册](references/editing-lessons.md)中的判断方法；它区分真实返工、预防性检查和具体案例，不把某一期坐标、帧率或白底方案固化成所有视频的要求。

## 制作顺序

1. 锁定内容与证据：检查当前素材、画幅、实际声音、源时钟；参考先看完整概览及关键动作相邻帧，不能只看联系图就宣称完成分析。
2. 有口播稿时先按[口播理解与素材选择](references/script-visual-planning.md)分析句意、上下文、人物情绪与段落任务，用[当前 B-roll 偏好](references/broll-preferences.md)选择保留人物或具体素材；先写清初态、动作、变化和结果，再选择特效、声音与镜头，按实际语音安排触发与阅读停留。新一期重新设计开场主事件，已有认可开场按范围保留。
3. 先做稳定布局，再连接运动；实际中文、图标、设备与内容比例在最终尺寸可读。先完成开头与代表性片段，用本期真实素材和音轨呈现预定风格。
4. 选择适合现有工程或参考的引擎。预设是动作起点，修改内容、对象与语义时间；不能只换标题、拉伸时长交片。
5. 按本期确认阶段导出和验证。样片确认后继续到实际完整 MP4 与可编辑工程；图片任务交图片。字体、主要中间帧、源媒体推进、音轨和尾帧做相称检查。

## 单一命令入口

从本技能目录运行，也可使用脚本绝对路径。`--` 后参数直接传给原后端；创建脚本仍拒绝覆盖已有工程。

```powershell
python -X utf8 scripts/ui.py status
python -X utf8 scripts/ui.py new --engine fusion -- --out <新工程> --scene F03
python -X utf8 scripts/ui.py new --engine base -- --out <新工程> --mode desktop --topic "本期主题"
python -X utf8 scripts/ui.py new --engine director -- --out <新工程> --preset continuous-codex-story
python -X utf8 scripts/ui.py new --engine editorial -- --out <新工程> --screenshot <截图> --title "本期主题"
python -X utf8 scripts/ui.py render --engine fusion -- --project <工程> --out <新导出目录>
python -X utf8 scripts/ui.py reference --tool toolkit -- search "UI"
python -X utf8 scripts/ui.py reference --tool rebuild -- status
python -X utf8 scripts/metaso_video.py status
```

`metaso_video.py` 是按需调用的视频素材生成入口，不替换现有渲染器；具体规划、只读连接检查和计费生成命令见[动漫视频生成](references/anime-video-generation.md)。密钥从本机环境或当前 Windows 用户的加密存储读取，不进入 Skill、源码或工程包。

`status` 只检查本地资源与入口，不联网、不安装、不启动旧任务。`new/render --engine base|fusion` 默认选择同机完整基础；缺失时才使用包内快照，可通过 `--base <目录>` 固定版本。已有工程应使用原创建版本与后端。`editorial` 只统一创建入口，渲染在生成的 Remotion 工程内按[模块命令](references/editorial-motion.md)运行。软件预设、参考复刻与编辑式模板依赖其原目录；缺失时明确说明，不能谎报为内置可用。旧脚本命令保持兼容。创建命令复制原模板，不会自动完成主题换色与内容设计。

## 反馈与交付边界

最新范围确认是“完整 UI 动效剪辑”，需要保留并按内容组合转场特效、运镜、排版、人物素材、界面演示和参考复刻。此前“高保真界面＋桌面手机联动＋连续丝滑运镜”是其中一个模块的质感要求，不应覆盖整个技能范围。2026-10-09 iPhone Use 首版样片被否定，第二版没有审美确认；它们都不是已认可的视觉标准。用户确认某个动作或风格描述，不等于确认整条样片。

新反馈落实到单一权威模块和当前工程，避免再创建一个同类技能。证据与验证按实际范围报告；文件存在、成功渲染、实际观看和用户审美认可各自独立。只修改本次请求覆盖的内容。

用户已要求用后续实际视频持续完善本次 B-roll 规则。按[反馈更新方式](references/broll-preferences.md#根据实际视频继续完善)记录原句与上下文、视频版本及时间点、反馈原话、局部修正与适用条件；已确认的方法更新回权威模块，项目参数留在工程。文字标注、问卷选择、样片认可和整片认可分开；本次写入不代表 49 个方案已拍成视频或通过样片验收，也不要求每期开新问卷。
