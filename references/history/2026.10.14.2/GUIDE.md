# 我的 UI 动效剪辑

这是通用剪辑导演，具体外观由账号或本期项目决定。用户给口播与素材，导演负责选材、动作、节奏和衔接；某段完全没有 UI 也可以。统一调用 `$ui-motion-fusion`，从下面四层按需读取，不一次加载全部文档。

## 四层入口

| 层 | 解决什么问题 | 何时读取 |
| --- | --- | --- |
| **1 · 主流程** [workflow.md](references/workflow.md) | 做什么、按什么顺序、口播与来源约束、样片阶段及交付检查 | 开始制作或继续工程时。口播任务再读[语义选材方法](references/script-visual-planning.md)与[本用户条件偏好](references/broll-preferences.md) |
| **2 · 账号风格** [style-profiles.md](references/style-profiles.md) | 本期长什么样、谁出镜、沿用哪个认可样片 | 账号明确时读对应档案；未明确时不套用阿刁身份或黑白紫。方木先读其样片／实现索引，沿用已有授权 |
| **3 · 效果与实现** [library.md](references/library.md) | 用哪个动作、现有什么源码、怎样创建和导出 | 先确定段落任务，再选择需要的模块。目录分别标明分析配方、已有实现、验证与认可范围 |
| **4 · 参考与历史** [history.md](references/history.md) | 方法从哪里来、以前怎样反馈、何处查旧规则 | 蒸馏、查证或复盘时；历史模板不自动成为当前规则 |

最短路径：**识别任务 → 主流程 → 适用档案 → 所需效果**。只改规则、静态图或局部画面时，仅处理对应范围；不触发整片流程。来源不足仍继续已明确的部分，实质影响结果且无法推断的缺口最多问一个简短问题。

## 决策只在一个地方维护

规则优先级：**本次明确要求 → 当前工程已确认设置 → 适用账号的最新反馈 → 所选模式 → 旧模板起点**。规则归属、兼容名称和更新位置见[模块映射](references/module-map.md)。

- **原创／融合**：账号与表达目的决定外观，参考提供动作和结构。
- **忠实复刻**：保留原片颜色、字体、画幅、时长及镜头路线，登记用户允许的替换与实际差异。
- **继续工程**：核对源码、母带、当前导出及认可范围，沿用有效配置；技能整理不授权换引擎、升级依赖或重剪已认可内容。

制作阶段与已有风格授权按第一层执行；方木的直接沿用授权保留。先理解句意与情绪，再选人物或 B-roll；原口播、真实操作证据和源媒体时钟按第一层保护。动漫表演、图形机制、软件窗口与设备均是可选能力，不强迫每期使用。

## 调用与边界

从本技能目录运行 `python -X utf8 scripts/ui.py status` 查看本机资源；这只证明入口存在。创建、导出和参考检索命令集中在[引擎路由](references/engine-routing.md)。当前后端没有统一 `--profile`，档案需要落实到工程；模板不会自动换色或完成语义设计。

六个旧名称继续兼容：[本机调用说明](references/global-use.md)。原源码、素材、56 项 O/X 记录、8 个 F 机制、103 条软件预设记录、230 条参考目录记录、16 条本地参考配方及字体库全部保留。这些集合有重叠、状态不同，不相加为“已验证效果数”。

文件存在、历史渲染、当前技术检查、实际观看／试听、用户认可各自独立。近期参考的总体喜爱不等于每条配方已实现；未获认可的旧样片不充当风格基线。新反馈更新单一归属模块并保留原证据，具体坐标和源时钟留在工程。
