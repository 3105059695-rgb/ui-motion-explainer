## 实际返工暴露的问题

### 1. 一张图停很久，后加转场仍像 PPT

- **用户反馈**：开头空，一张图耽误太久，缺少转场和吸引力；多个题材反复出现这个问题。
- **判断**：问题在于画面没有推进含义，不能仅靠图片放大或整页飞入解决。
- **改法**：给图明确用途，先建立对象，再聚焦正在讲的细节、差异或结果，让这一对象承接下一画面。静态图片也可参与连续叙事，不需要强制生成视频。
- **检查**：每次画面变化是否增加信息？停留时观众知道看哪里吗？如果只是换标题和卡片，回到内容重新设计。

### 2. 做了“漂亮开头”，观众却看不懂前后对比

- **用户反馈**：数字人口播底图一期要表达“前期与后期的对比”，却没有把差别直接展示清楚。
- **判断**：没有先识别这段口播的核心任务，把包装排在表达之前。
- **改法**：清楚建立“前／后”或“问题／改善”的对应关系，用可比较的对象和尺度展示，再圈出关键差异。示意素材与真实成果分别标清。
- **边界**：不是每期都必须做对比；只有本段需要比较时才采用。用户之后要求“直接展示这张图片”，应使用指定原图，而非再生成替代品。

### 3. 素材看起来相关，却没有解释正在讲的事

- **用户反馈**：提供了充分素材，成片仍难以看懂；餐饮一期又补充了具体参考封面来增强吸引力。
- **判断**：文件名、主题相似或好看不足以证明适合这个语义段。
- **改法**：每项素材都能回答“看见它，观众能理解什么”；操作、事实和比较用对应证据，情绪或抽象关系才用合适示意。
- **检查**：原句、素材、动作、结果是否对应；不要把既有用户素材放在一旁，只用泛化卡片或装饰图。

### 4. 没挡脸，却挡住了手臂

- **实际案例**：《失业手册》开头浮层挡到人物伸出的前臂。
- **判断**：只根据静态帧或脸部位置划分“空白区”，忽略整段动作范围。
- **改法**：看完整手势过程，给脸、头发、手、前臂和字幕留出动态安全区，再决定浮层位置、尺寸或出现时机。
- **检查**：抽查手臂伸展最大、转场中间态及稳定画面；面板本体、阴影和入场路径都要避让。不要复制本期像素坐标到下一条素材。

### 5. 黑底缩小了，画面还是很沉重

- **实际案例**：《失业手册》v2 解决了遮挡，但大黑底仍影响观感；v3 移除大底板，用户随后接受这次修改。
- **判断**：把“黑白紫配色”误解为必须有一整块黑容器；更根本的问题是容器面积与必要性。
- **改法**：先判断能否直接在原场景上组织信息。该期亮背景适合小白色浮层、轻边框、柔影、深色文字和局部紫色。
- **边界**：这不是禁用黑底；深色场景或需要高对比的信息区域仍可使用。只把黑板换成白板，也未必解决空、重和遮挡。

### 6. 想要 AE 丝滑，却只增加“动得多”

- **用户反馈**：开头需要特效和丝滑转场；本轮进一步明确阅读阶段有变化，但不要太炫。
- **改法**：共享对象交接、焦点推近、遮罩露出真实下一场、利落启动与柔和减速；动作落点配音效。强弱由内容决定，结果阅读只做轻推镜或局部强调。
- **检查**：阅读焦点是否稳定，文字是否清晰，前后对象是否可追踪。恒定漂移、频繁弹跳、任意快切不等于连续叙事。
- **边界**：“AE 感”是效果要求，不等于交付原生 `.aep`；交什么工程应准确说明。

### 7. AIGC 衔接顺，却把未认可的 UI 当成风格基线

- **原话与任务**：“我就是想要以后的剪辑里面aigc能搭配着这么顺”之后，用户同条消息指出“我不是写好了ui风格是什么的吗？怎么又做成这样的”。任务是继承生成素材到 UI 的自然接力，同时保持正确外观；正向半句不能覆盖后半句否定。
- **原材料与可见交接**：样片把按句意生成的连续动作素材对齐口播，再将同一对象交给精确 UI 动作。保留这一关系；物理纸张、工位和黑袖手不是固定道具。
- **失败原因与修正**：原实现把“白、黑、淡紫”的概述及未认可原型当成完整基线。后续必须依据当前 Fred 实际参考检查主体尺度、字级、材料层次和动作；几处色号相同不等于风格相同。
- **可迁移与结果**：适合跨载体接力的解释段；模型、纸张、布局、时长不照搬。此样片只确认 AIGC 融合，不确认其 UI 或整片。[原话和拒绝图指针](evidence/full-transfer-feedback-20261014.json)。

### 8. GEO 解释只有代码特效，开头几个小卡片过于单调

- **原话与任务**：“全是代码的特效，没有一点儿真实的痕迹”“开头也是，太单调了，就几个小卡片”。本段需要观众认识具体处境与实际材料，而非只看抽象标签运动。
- **材料与构图修正**：该次修订引入四张自然摄影感 AIGC 场景和更贴合语境的 UI 操作，保留原人物与原声时钟。照片负责可辨识处境，UI 负责操作及反馈，不能只拿场景装饰背景。
- **可见变化与交接**：按每段对象的操作、状态和结果设计，再让其接入下一句；不是把代码动画统一换成照片轮播。原稿具体句意与时序仍应从原项目修订计划读取，不能在此补造。
- **可迁移与结果**：迁移“解释任务决定载体”和“可信材料参与事件”。装修房间、桌面、手机、四张图的数量不通用；“代码不好”也不是结论。用户确认在原 Skill 学会创造这种感觉，不认可固定整片框架；GEO 修订整片审美和完整听审未由此推定。[原话、前后版本与范围](evidence/creative-judgment-feedback-20261014.json)。

### 9. 一直从熟悉的旧片换字，已有参考并没有真正参与设计

- **问题语境**：用户指出“老是逮着一个视频薅起来”，同时询问秋芝研究为何没有用上。任务是稳定继承风格，并用完整参考能力解决不同内容，而非每次重新问审美。
- **选择修正**：先确定本期事件，再从已有研究和效果库定位相应构图、对象关系与实际源码；看实际预览后取舍。旧认可只作为其范围内的质量证据，不因“最近、第一条、可运行”支配新片。
- **可见变化与交接**：不同解释任务应有各自对象和变化；不能把用途、成果、机制、处境全部改成“输入→发送→文字答案”。实际操作确实如此时仍可用该链。
- **可迁移与结果**：不规定作者配额或效果数量；Fred 仍是当前整体风格，其实现可组合适用来源。2026-10-19 候选接入和 69 项检查证明技术入口修复，不证明新片效果达标。[真实修复与未完成项](evidence/window-lessons-20261019.md)。

### 10. 把“不重复同一部片”误解成“用户不再要 Fred”

- **本轮原话**：“我喜欢的视频风格就是fred talk的风格，所以不要乱给我想风格，我就说每次新开怎么都要重新说一遍。”
- **失败原因**：把内容编排的自由与整体风格的自由混在一起，导致新窗口再次改变用户已经选定的方向。
- **修正后的决定**：Fred Talk 整体视觉与剪辑为持久默认；先从实际参考看实体黑色载体、醒目紫色重点、大字级、前后深度和连续变化，再用效果库实现。每期更换的是材料、具体事件、镜头路线及原声 cue；旧片的品牌、人物和时间轴不继承。
- **结果与边界**：本轮用户纠正确认的是默认方向，不是新作品的认可。旧逐图反馈及历史样片原文保持；当前执行以更晚的明确原话为准。[可供新窗口读取的当前合同](evidence/fred-default-correction-20261020.json)。

## 工程里采用的防回归方法

跨库候选入口的实际修复、使用方法和技术证据见上方案例 9；下表只保留不重复的工程检查。

以下是具体修订和潜在风险的预防措施，不宣称每一项都曾引起用户投诉。

| 风险 | 有效处理 | 检查与边界 |
| --- | --- | --- |
| 旧通知未退，新问题已进入，同一区域文字叠影 | 先让出阅读权，再引入新内容 | 查转场相邻帧和稳定帧；瞬时低透明度可以存在，稳定信息应清楚，淡入淡出时点随当期设计 |
| 开头改了位置，正文仍从旧位置开始 | 共享对象的开头末态与正文初态使用相同几何，再展开 | 看交界前、交界点和交界后；不把本期 7.4 秒与 0.75 秒当固定值 |
| 两份人物视频都带口播，重复叠声或对齐偏移 | 先核对覆盖句子，再选单一母带，画面切换不重复加声 | 检查实际音轨、源内区间和交接；是否降噪或另混音依本次要求 |
| 动效时钟牵动人物口型 | 源媒体与图形动画各用正确时钟 | 导出帧中的视频确实推进；检查口型、字幕、声音的对应关系 |
| 一点改动导致整片重复制作 | 沿用工程，仅重做受影响部分 | 复用旧渲染段前核对素材、声音、样式和交接依赖；复杂缓存校验只在需要时使用 |
| 技术通过被说成“全片已审好” | 分开记录格式检查、实际观看／试听、用户反馈 | 文件存在、50 fps、解码成功不证明画面丝滑或全片听审；后来认可另行记录，不篡改旧证据 |

本轮用户截图还提及“选书、划线、归档、复习”的编排及黑块遮字。当前资料没有为这段说明绑定精确成片版本、时间点和原始认可，因此只保留为后续定位线索；不补造成功案例、时间码或声称已经核查那条视频。
