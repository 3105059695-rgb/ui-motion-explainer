# 实际画面的检查与修正

本页维护实际查看与修正方法，不另设审美和审批流程。Fred Talk 默认、AE 感与禁忌读[审美偏好](aesthetic-preferences.md)，检查阶段与交付读[主流程](workflow.md)。下面的软件和手机细节只在对应画面出现时适用。

## 用实际样片校准

把实际 Fred Talk 参考及本期输出并排看，记录本段保留与改变的设计关系：主对象占比、窗口展开与让位、前后景与遮挡、字重及阅读顺序、重点改变时的景别、动作后的停留。续作再对照已认可片段的实际版本。

先静音检查对象关系与注意力，再结合原声正常速度查看完整事件及前后交接。检查是否看得懂本段，材料是否与口播有关、是否只保留移位缩放而丢失构图和层次。关键帧漂亮、API 调用和来源哈希都不代替这一步；抽帧只能证明所见状态。

用户指出退步时，回看被比较作品的真实素材与实现，定位之前有效而本次丢失的表达，不能只归因于配色或素材数量。被否定版本及修正原因查[剪辑案例](editing-lessons.md)，不靠重剪已认可部分证明创新。

## 从低保真到可信界面

- 使用符合主题的软件结构：窗口、侧栏、当前路径、工具栏、主内容、输入区和结果容器各有职责。手机保留对应系统的状态栏、机身比例、应用结构、键盘和手势条。标题、段落、图标都使用实际内容。
- 字号、字重、行高按阅读顺序分层；使用可随工程交付的中文字体。代码名和元信息降低权重，主要内容在导出尺寸下可读。长内容重新排版或局部聚焦，不挤成小字。
- 标题、重音词和数字可按内容选用[乔木字库与花字](qiaomu-typography.md)中的本地搭配；花字服务强调，正文保留清晰阅读，真实应用内的字体仍以对应界面为准。
- 边距以共同基线和视觉对齐确定。嵌套圆角协调，按钮、输入框和图标描边一致；光学位置优先于机械居中。图标用清晰的 SVG／真实资产，避免混用风格和用方块假装应用图标。
- 顶栏／当前项／结果区通过结构色建立层级；实际配色依据本期 Fred Talk 参考或用户明确覆盖，不能由后端模板决定。边框轻而清楚；阴影范围与距离对应对象位置，不靠大片发光。
- 先判断容器是否必要。大片空黑底在亮人物画面里会显得沉重；可直接利用原背景，用局部小浮层承载信息。删除底板、缩小有效面积与改善层次，比机械把黑底换白更能解决这类问题；深色场景仍可按需使用黑底。
- 截图与视频按最大显示尺寸选择源清晰度，保持等比。窗口变化优先调整遮罩和外部容器，正文避免非等比拉伸。导出为 1080p 不会恢复低清素材细节。

## 连续运动与注意力

同一对象持续：输入框提交后成为同一任务；文件到达新容器后展开对应内容；手机始终保留方向与位置线索。既有状态在过渡中让位，新状态从明确来源进入。

动作起步干脆、减速柔和；强调的变化幅度与语义重要性匹配。阅读阶段允许静止，需要引导时才轻推镜或局部高亮，字幕与重要句子保持稳定、清晰；不同时叠加多种循环效果。快速位移可用短运动模糊，清晰读字阶段关闭；弹跳和透视只在需要时使用。

镜头推近当前操作点，其他内容让出注意力；完成后回到总览或交给下一对象。一个镜头与一个窗口内层不要同时独立放大同一内容。不要把每句话都改成新标题卡，也不要只给静态截图缓慢放大就当作完整 UI 交互。

## 检查中途与首尾

- 查看稳定状态，也查看入场、遮罩交接、放大、收束和转场中途。重点检查黑块／蒙版遮字、长文溢出、双脸、脸／头发／手／前臂和字幕被动态遮挡；只看开始与结束会漏掉这些问题。
- 有操作时核对触发先于反馈、结果有阅读时间、对象和去向一致；人物或情绪段不强行凑“总览、操作、结果”。
- 核对人物视频和真实材料持续推进，原声不重复、不调速、不冻结尾帧补时；字幕、口型与源时钟一致。播放首尾及尾音，确认没有多余空白、突断或重复。
- 正常速度试听原声与动作声，检查重音／动作落点、声音遮盖和转场连续性。未实际试听或完整观看时，留下明确范围。

## 发现问题后在同一工程修正

| 观察到的问题 | 先修什么 | 修后复看 |
| --- | --- | --- |
| 素材与原句无关、只有标题列表 | 段落任务、材料与可见事件，保留既定整体风格 | 完整事件及上下文 |
| 外观偏离 Fred Talk、只剩通用缩放 | 回对参考的布局、材料层次、字级和动作组织 | 同一参考与本期连续输出 |
| 黑块遮字、人物或字幕被挡、变形 | 遮罩范围、层级、裁切和对应动作区间 | 问题前后及中间态 |
| 看不清结果、动作与口播错位 | 原声 cue、阅读停留、变化幅度；不擅改原声 | 正常速度声画与前后交接 |
| 素材冻结、重复音轨或依赖失败 | 媒体时钟、源文件和实际入口，保留可用工程版本 | 受影响区间及对应技术检查 |

计划和实现一起更新，只重做受影响部分；修正后确认没有丢掉先前有效的表达。若需要新素材或当前后端不能实现，记录明确缺口和可行替代，按授权继续可完成的部分，不用空壳画面或虚构“已通过”填平问题。

同一交付记录写片内时间、实际问题、修改与复查范围；技术预检、视听判断、用户认可分别保存。通用检查经验更新本页，审美偏好更新其唯一入口，具体版本及反馈留在案例和项目。
