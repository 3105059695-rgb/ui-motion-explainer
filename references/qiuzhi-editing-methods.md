第三层的段落配方说明。从[可用效果库](library.md)按表达任务进入；本文件不替代[主流程](workflow.md)、[账号档案](style-profiles.md)或[用户 B-roll 偏好](broll-preferences.md)。详细数据在 [semantic-editing-recipes.json](semantic-editing-recipes.json)，来源范围在[证据记录](evidence/qiuzhi2046-methods.json)。

这次吸收的是参考如何让画面帮助观众理解：作品先展示、真实证据聚焦、同一对象交接、比较与因果、角色在一个空间中连续取用和组合。不是把长教程章节模板变成所有视频的剪法，也不将参考的人物、黑底、荧光色、品牌或坐标设成全局默认。

## 先作判断，后选配方

1. 通读原句和前后文，判断这一段承担事实、过程、比较、解释、情绪、转折还是结果；有原声时听重音与停顿，没有时标记情绪待声音校准。
2. 写清观众此刻缺少哪一步理解。先决定保留人物、使用真实素材/实操，还是需要图形机制或 AIGC 事件。人物讲述本身足够时不强加 B-roll。
3. 写出“初态 → 可见触发 → 变化 → 结果”。抽象概念落成可感知的物件和关系；人的情绪落成刺激与身体动作，不是遇到一个词就调用一张图。
4. 再选蒙版、遮挡、转场、匹配剪辑、对象交接、推拉、比较或节奏停留。每个动作要增加理解，不能用转场密度代替内容。
5. 给这一段设计入口与出口，沿用原口播和已有素材身份。配方只复用方法，每期重新设计主事件、角色、物件、环境及镜头路线。

### 真正可复用的是事件和素材关系

- **蒙版/局部放大**：标注当前必须读清的一处，保留来源位置；目标变化后再转移焦点。真实录屏状态先发生，外部标注后解释。
- **匹配剪辑/对象交接**：同一物件在两种媒介中继续行动，或前一份产物成为后一段输入。仅形状相似不能冒充同源。必要时直接切比强行变形更清楚。
- **遮挡/揭幕**：前场存在可理解的入口，后场已经真实加载。物体掠过、容器扩展、镜头进入空间均可，不能只有一张黑幕。
- **运镜**：全貌负责定位，推近负责看清变化，回拉负责看懂结果与关系。镜头与对象的缩放分开，避免文字/人物被双重拉伸。
- **比较/因果**：对象、数值和状态从同一份分镜事件表产生；不把不同条件并排成优劣证据，不把剪辑快慢冒充真实效率。
- **节奏**：解释时让动作推进，信息到位后给阅读，情绪转折保留反应。切换随意义而变，不固定每几秒换卡；未听参考音轨，不能从抽帧推断其 BPM、音效或音画同步。

以上都可用于短口播、生活隐喻、工具介绍、实拍混合与原创故事。章节路标仅在内容确需定位时使用，不是配方中心。

## 三个 AIGC 配方如何真正用于制作

S08–S10 的 `generation` 内有可填的 `still_image_prompt_template` 与 `video_prompt_template`，并列出角色参考、世界关系、动作拍点、入口/出口、约束和合成检查。它们是本技能的制作设计，不是对作者所用模型或提示词的推断；本次尚未调用生成、没有新素材验收。

使用时先读取当前账号的角色和整体画风。没有明确角色时按当前任务解决身份，不跨账号沿用阿刁女主，也不复制秋芝角色或炉子吉祥物。首帧是单个可播放场景；多格分镜可以辅助规划，但不将整张漫画格作为最终视频。

### S08：把取用与组合演成事件

可填关系示例：一句“把两种能力组合起来，才能把这项任务做完” → 两件具有不同接口的工具模块 → 人物先取第一件、接第二件 → 插接后实际完成一个任务。物件对应能力，连接动作对应组合，使用后的改变对应收益；不能只是两张词卡碰撞后闪光。

提示词需填完整：原句/上下文、角色参考、场景画风、两物件及其位置、组合方式、新产物、实际使用动作和后果、进入/退出锚点、可用时长。先让观众认出物件，再切手部和结果；空间、左右关系和数量跨镜不变。

### S09：把“丰富意图变少”画出来

可填关系示例：一句“准备了一整套要求，说出口却只剩一句‘高级一点’” → 有布局、材质、灯光细节的完整小场景 → 穿过表达媒介时依次失去细节 → 终点仅剩一个简化轮廓，准确文字由后期加入。该句仅为填参示例，不替换用户口播。

“脑中完整画面→输入只剩几个词”的解释方法已有[历史样片认可](evidence/anime-semantic-feedback-20261013.json)。继承的是用具体变化帮助理解，不是固定鲸鱼城市、五秒或三个镜头。新一条仍按新口播设计并检查；参考 `network` 的资料卡并未出现碎裂过程，不能将本配方的重建画面写成原片事实。

### S10：把情绪放回事情里

可填关系示例：任务完成后伸展庆祝 → 新消息进入 → 视线发现并读到变化 → 身体僵住、双手落回桌面 → 重新拿起工具。先定义刺激和后续行为，再定景别与转场。真实人物已经演出了对应情绪时可以保留实拍。

必须给出原句的情绪依据；无音频时先按文本推测并标待校准。只微笑、比 V、转头或发梢摆动不能替代句意需要的变化。生成动作峰值对齐原口播，不能拉扯原人物嘴型和源时钟。

### 接现有生成通道与工程

1. 在本期工程中把选定模板所有 `{{变量}}` 填为具体内容，保存 UTF-8 提示词；角色参考和场景参考仍单独保留。
2. 按[动漫生成模块](anime-video-generation.md)用已有客户端离线形成计划，例如：

```powershell
python -X utf8 scripts/metaso_video.py plan --prompt-file <本期完整提示词.txt> --out <本期新计划.json> --duration <按原声确定的秒数> --resolution 768P --ratio <本期画幅>
```

3. 首帧/引用模式和计费提交按现有模块真实参数与当前预算授权处理；Skill 更新不授权收费。这里不安装新运行时、不发送参考图、不执行生成。
4. AIGC 负责人物/环境表演；准确字、真实界面、可控遮罩与碎片可由代码合成。原口播保持不变，生成音轨不自动混入。
5. 接入后检查“发生的变化是否解释了原句”，再看人物身份、动作/镜头连续、入口出口和结果停留。API 成功、素材有动作、画风接近，均不是语义和审美验收。
