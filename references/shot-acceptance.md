# 逐镜剪辑与验收

从同一期原声、现有字幕和镜头计划开始。以下命令均在 Skill 根目录执行。用户要看样段时，把两个可播放文件连同对应的对照页交付。

| 制作时 | 留在本期工程里的依据 |
| --- | --- |
| 按每条投稿已登记的职责读完整动作。 | 每处实际借用分别填写参考类型、参考起止秒、成片帧段、实际看法和具体借用。只看图、读记录、播放工程重演都如实标记。 |
| 同一条原声选一句有具体矛盾、后果或马上能看见的动作做开头。 | 写出“前三秒听到了什么，接下来想知道什么”。从自然换气处开始，给 8–12 秒的原声片头。用户指定的开场和原稿顺序优先。 |
| 切实景前回答“继续看讲话的人，会少看懂什么”。 | 记素材的原出处、可见主体、动作、所支持的句子和信息增量。普通道路只证明拍到了道路，航展画面只证明拍到了航展。涉及具体路测或电池项目时，找到对应来源再切。 |
| 在实景占满屏幕时保留品牌和物体原色。 | 人物小窗只出现在能增加信息且无第二张脸的位置。圈出整段的动作轨迹、片内文字和本期字幕区。裁切或缩放后以最终画幅为准。 |
| 按原声中实际出现的关系选择 HyperFrames 动作。 | 层级用逐层建立和焦点转移。协作写出上游交付物、下游接手和结果，用对应材料演出，颜色继承主审美。 |
| 大规模渲染前看两段。 | 检查字体、口型交接、素材露出和手机上的第一视觉落点。有问题先改片段。保留实际观察范围。 |
| 只改一句字幕。 | 用原声时码和字幕 ID 定位，校验原文字，只保存该条。画面和声音独立于对白字幕。 |
| 交付时说清谁能编辑什么。 | 播放记录写解码、实际看片范围和是否带原声。视觉意见写观察到的具体镜头。编辑能力写 SRT、HTML/JS/HyperFrames 图层、烘焙画面及实际试过的剪辑软件。 |

## 镜头对照和实景

在普通 `direct -- save` 补丁的镜头 `set` 中保存以下字段。时间是所选参考播放器自身的时钟。`original` 为原片，`sample` 为公开样片，`replay` 为源码或动作重演。实看方式可为 `normal-sound`、`normal-silent`、`frames`、`notes`。借动作默认 `aspect: motion`，这类镜头需要连续观看所借区间才能进入整片导出。只借构图、颜色或材料时用 `layout`、`color` 或 `material`。若依据是静帧或笔记，填 `basis: still` 或 `basis: notes` 并省去 `seconds`。新电脑缺少已经登记的原片时，对照页标出替代来源。

```json
{"borrow":{"basis":"original","seconds":[111.8,114.5],"seen":"normal-silent","use":"先让观众找到原文中的同一行，停稳后再放大查询结果。"}}
```

每个对照页有“此镜头的链接”，可以单独打开。左边播放成片，右边播放登记的依据，可单独打开声音。入口是 `videos review --project 成片工程 --media 成片.mp4 --serve`。镜头归档的来源时间与实际观看方式分别保存。

以实景为主的连续切换填进镜头计划的 `cutaways`，或用 `save` 的 `master_revision` 更新 `master.cutaways`。下面是结构示例。所有帧号、出处、主体和矩形都换成本期实测值。`origin` 使用首次取得的原件记录或原始媒体地址，后续裁切、改名保留该值。一个原件可再次出现，选材统计按原件合并。普通镜头内的素材也可在绑定上保存同结构的 `footage`。

```json
{"start_frame":395,"end_frame":485,"path":"材料/装配工位.mp4","in":24,"main_has_face":false,
 "seen":"frames","inset":[0.02,0.70,0.20,0.20],"subtitle":[0.04,0.01,0.92,0.08],
 "protect":[[0.27,0.11,0.67,0.63],[0.38,0.81,0.24,0.12]],
 "footage":{"origin":"本期素材索引中的原件 ID","subject":"计算托盘装配工位","claim_subject":"计算硬件的实体形态",
 "use":"illustration","gain":"能看见装配头对准托盘后落向接口。"}}
```

直接证明具名事实时填 `use: direct`，主体和被证明的对象使用同一个已核实的名称。标作举例的镜头只用来解释一般机制。主画面有脸或小窗挡动作时去掉 `inset`。保护区用画面比例 `[左,上,宽,高]`。剪辑者核对来源真实性和信息增量，程序核对文件、时长、几何与登记的身份。

## 按原声建立层级

`videos hierarchy --cues 本期层级.json --out 本期层级镜头` 生成可供 HyperFrames 渲染的原生工程。四层依次进入，最后把焦点交给原声指定的层，其他层仍作上下文。下例时间是示范，实际要听本期原声逐词取点。`focus` 从零数。

```json
{"duration":5.4,"levels":[{"at":0,"text":"芯片"},{"at":0.9,"text":"云"},{"at":1.8,"text":"模型"},{"at":2.7,"text":"应用"}],"focus":3,"focus_at":3.7}
```

## 两段原声检查

先运行 `videos compose`。早期仅做两段可加 `--preview`，其余尚未定时的投稿仍留在原剪辑计划。再运行主入口中的 `videos proofs`。它从当前播放器按主时间线只画这两段，配回同区间原声。传 `--captions 本期.srt` 时校对片上显示对应字幕。`--bridge` 要跨过两侧剪点。确实没有人物或有出处的实景时，保留适合该片的讲法，使用 `--alternative "实际检查的段落及原因"`，交付注明原转换未验。

打开两个 MP4，在手机尺寸看完整动作和前后剪点，听同段原声。用 `videos proofs --project 成片工程 --observed normal-sound --note "两段实际看到了什么，发现什么，如何处理"` 保存观察。只看画面用 `normal-picture`，只查手机抽帧用 `phone-frames`。整片另按原速带声复看。

## 单条对白修改

```sh
python -B -X utf8 scripts/ui.py direct -- captions --project 本期工程 --import-srt 原有字幕.srt
python -B -X utf8 scripts/ui.py direct -- resume --project 本期工程 --at 00:39.40
python -B -X utf8 scripts/ui.py direct -- captions --project 本期工程 --at 00:39.40 --expect "查到的完整旧字幕" --text "只改一个字的新字幕"
python -B -X utf8 scripts/ui.py direct -- captions --project 本期工程 --out 修订.srt
```

换窗口时 `direct -- captions --project 本期工程` 返回上次的时码、字幕和镜头。字幕重叠时用 `--cue` 指明条目。已有外部剪辑项目也可直接导入 SRT。要关联镜头，可提供同目录的 `caption-shot-map.json`，格式为 `{"fps":25,"shots":[{"id":"镜头名","start":900,"end":1050}]}`，起止单位是帧。

要导出可开关对白的 MP4，用 `direct -- captions --project 本期工程 --media 净画母版.mp4 --out 修订.mp4`。音视频压缩数据直接复制，耗时在读写容器和校验文件。和 MP4 一起保留同名的 `.mp4.captions.json`，对照页用它关联净画母版和本版字幕。软字幕的实际位置由播放器决定。交付有指定避让位置或平台要求烧录时，从净画母版、修订 SRT 和最终字幕位置另行编码，单列耗时并检查目标画幅。已经烤进画面的字幕或标题需回对应镜头源码。只有在目标剪辑软件里实际导入、修改、重新打开并核对后，才把该项写作软件内可编辑。
